# 工程经验要在下一次动手前生效

保留现有skill库、参考和工程样板，不因重构流程删除有效方法。技能用于改变操作，不是增加必读清单。

## 使用时

从当前任务查询[工程索引](../knowledge/engineering-assets/catalog.json)，读命中的操作卡和具体样例；记录实际采用方法与结果即可。Revit问题读Revit方法，CAD问题读CAD样板，版面问题读表达技能；不要求每次读全库。

首个未知操作做小样／回滚试算，真实看对象和图面后扩展应用。参数化脚本重跑需能识别已有对象；版本／软件变化后重验受影响方法，不把历史项目成功套到所有环境。

## 反馈回写

出现重复故障、用户纠正或可复用方法时，收尾执行：

1. 记录具体症状和来源版本，区分用户观察、日志／数据与推断。
2. 查明原因，确认有效修复与失败做法；未找到原因就保留“待核”，不包装成教程。
3. 优先更新原skill的对应段落、示例、检查项和工程索引，避免再新建一个互相矛盾的skill。
4. 通用机制写技能；项目坐标／ID／字体／纸幅／容量阈值写项目预设。稳定检查编号保留，过时结论标替代关系。
5. 标记验证级别：reference-reviewed、project-evidence、offline-tested或指定版本host-verified。没有本轮宿主测试，不升级验证标签。
6. 更新检索关键词，使下次“门切不开墙”“剖面像立面”“图内字太小”等真实问法能命中方法。
7. 脚本有变更就跑相关真实小样／读回测试；文档改动核链接与一致性，不为低影响文字修改新造测试。

模板：问题／证据 → 根因 → 推荐操作 → 验证方法 → 适用限制 → skill／样板位置。一次问题只保留一份主结论，项目日志链接它。

## 长文与旧规则

长技能入口优先给任务路由，详细案例和宿主说明按需读。原技能中固定角色、旧人工Gate、硬编码机器端口和项目阈值不能覆盖当前用户要求。修订时保留有效工程内容及历史来源，不能把原技能整库删除后只留几句口号。

历史档案不作为新任务的默认指令。新技能只有独立能力边界且确实需要时才创建，不每做完一包都建新skill或报告目录。

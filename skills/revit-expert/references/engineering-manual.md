# Revit工程方法资料

按当前任务只读相关小节；原有工程内容保留。历史角色、审批与固定项目参数不覆盖主流程；检查只限本轮受影响范围，不默认全量复查。

## 2. Revit 方法优先级决策树

### 2.1 强制优先级

始终按以下顺序判断，不得倒置：
1. Revit 原生系统构件。
2. 成熟 Loadable Family。
3. 参数化 Family。
4. 必要的 In-Place 或 Mass。
5. 必要的混合构件方案，仍尽量保留原生对象语义。
6. 最后才允许纯几何 workaround。
脚本／API是执行手段，可以创建上述任一级的原生构件；不能因为用API就降级，也不能因为专用tool方便就选错对象类别。先选择工程对象与更新逻辑，再选择界面、专用tool或代码。
这里的顺序是方法选择顺序，不是必须逐项实际尝试失败后才能进入下一项。
只要高优先级方法合理满足类别、约束、编辑、统计与出图，就停止下探。
选择依据是“后续变化如何发生”，不是“眼前哪个命令最快”。

### 2.2 决策前六问

先问对象是否有 Revit 原生类别，且应参与房间边界、切割、连接、标签或明细表。
再问对象是否是连续建筑系统，而不是离散产品。
再问对象是否会出现两次以上、跨楼层复用或跨项目复用。
再问对象是否应由类型尺寸控制，还是每个实例都不同。
再问对象是否必须依附墙、楼板、屋顶、面、工作平面或标高。
最后问对象是否仍处于体量推敲，尚未形成可出图构造。
同时判断它会影响多少张图、多少个表和多少项评分。
无法回答类别、宿主和后续变化方式时，暂停建模并补齐判断。

### 2.3 优先级 1：Revit 原生系统构件

适用判断：对象属于墙、楼板、屋顶、天花、楼梯、栏杆、幕墙等建筑系统。
适用判断：对象需要房间边界、层次材料、自动连接、剖切表达或系统规则。
适用判断：对象变化主要来自标高、边界、坡度、路径、附着或类型。
默认做法：先用系统类型、实例约束、边界草图、轮廓编辑和附着关系解决。
优点：一次修改可同步平面、立面、剖面、三维和明细数据。
优点：保留正确类别、可见性、过滤、标签和统计入口。
风险：错误类型、错误标高或错误边界会把问题传播到整套成果。
检查：至少在平面和剖面确认边界、连接、标高与剖切表现。
不得降级：不能因为 Generic Model 更容易画，就用它冒充系统构件。

### 2.4 优先级 2：成熟 Loadable Family

适用判断：对象是门、窗、家具、洁具、灯具、设备或其他离散标准构件。
适用判断：可靠内容库已有正确类别、宿主、尺寸、可见性和参数的族。
适用判断：对象需要多次放置、独立编号、标签、明细表或跨项目复用。
默认做法：先查询当前项目可用类型，再加载可信、轻量、版本兼容的成熟族。
优点：避免在一至两周课程作业中重复造轮子。
优点：一个类型更新可带动全部实例。
风险：厂家族可能高面数、类别错误、参数污染、宿主不合或版本不兼容。
检查：加载前后核对类别、宿主、单位、类型参数、平立剖表达和文件性能。
不得降级：不能因族需要清理就立刻改用原位实体。

### 2.5 优先级 3：参数化 Family

适用判断：成熟族不能满足关键尺寸、造型、标签或统计需求。
适用判断：对象会重复，且变化可被少量明确参数描述。
适用判断：对象需要形成项目资产或在多个位置保持同一规则。
默认做法：先选正确模板和类别，再建参照平面骨架、尺寸参数和最少几何。
参数规则：同类型一致的尺寸、材质和构造选择使用类型参数。
参数规则：编号、安装高度、实例备注等逐件变化信息使用实例参数。
参数规则：跨族、标签、明细表互通的数据才使用共享参数。
优点：把多处修改集中为类型或参数修改。
风险：公式过多、嵌套过深、阵列未限值会造成 flex 失败和性能问题。
检查：最小、典型、最大三种尺寸均 flex，再加载、标注和出表测试。
不得升级复杂度：一次性物件不因“可参数化”就必须做复杂族。

### 2.6 优先级 4：必要的 In-Place 或 Mass

使用 In-Place 的条件：对象仅限本项目、确实唯一、强依赖周边不规则几何。
使用 In-Place 的条件：系统族和合理 Loadable Family 路径都不能表达。
可接受对象：一次性艺术装置、独特展台、非重复自由曲面室内造型。
使用 Mass 的条件：处于体量、退台、面积、日照或自由曲面方案研究阶段。
使用 Mass 的条件：需要先找形，再按面生成墙、楼板、屋顶或幕墙系统。
默认做法：In-Place 明确类别、名称、位置、用途和责任。
默认做法：Mass 定型后把关键外皮转换或重建为可出图系统构件。
优点：容纳真正的项目例外和早期形体探索。
风险：难以复用、统计、替换和维护；Mass 转构件后仍可能有接缝与材料问题。
不适用：门、窗、普通家具、常规设备、重复幕墙单元、普通楼梯和栏杆。
检查：在平面、剖面、三维中确认它不破坏房间边界和主要构造表达。

### 2.7 优先级 5：特殊情况脚本或 API

适用判断：任务规则明确、重复量大、输出可验证、操作可回滚。
适用判断：原生 UI 或现有 MCP 工具无法高效完成批量编号、参数写入或规则创建。
适用判断：至少重复约二十次，或一次涉及大量元素，自动化收益高于测试成本。
默认做法：写明输入、规则、预期输出、不应改变的对象和回滚方式。
默认做法：先在副本或小样本运行，再用 Schedule、Filter 和视觉抽查验证。
优点：减少重复键盘操作和命名不一致。
风险：错误规则会被高速放大；版本、参数名、类别和 package 依赖会导致失效。
不适用：创作性布局、材料审美、剖面叙事、只改三至五个对象或无法验证的几何重建。
不适用：截止日前首次引入未知脚本、未知 package 或大规模删除逻辑。
检查：脚本 success 后仍检查元素数量、类别、范围、参数、平面、三维和 warnings。

### 2.8 优先级 6：纯几何 workaround

只在前五级都不成立且交付目标确实需要时考虑。
纯几何 workaround 指缺少正确类别、宿主、参数或系统语义，只追求外观相似的几何替代。
允许条件：对象不参与房间边界、门窗洞口、标签、明细、连接和关键剖切。
允许条件：对象只服务少量明确视角，且不会被误认作正式建筑构件。
允许条件：已记录原因、受影响视图、替换风险和 本次图纸复核 检查点。
优点：可在极端限制下补足非核心视觉信息。
风险：修改不可传播、图表数据失真、剖切错误、接手者误判。
不适用：任何主体墙、板、屋顶、门窗、楼梯、栏杆、房间边界或需统计对象。
绝对禁止：把 workaround 伪装成可编辑、可统计的 BIM 构件。
检查：在成果说明中显式列为例外，并确认不影响规范图纸。

### 2.9 方法例外记录格式

记录对象名称与 ElementId 或可唯一定位信息。
记录实际 Revit 类别与预期建筑身份。
记录采用的优先级层级。
记录未采用更高优先级方法的具体原因。
记录对平面、立面、剖面、三维、标签和明细表的影响。
记录视觉检查视图与检查结果。
记录未来方案变化时的替换条件。
记录批准该例外的版本和责任人。

## 3. 构件正规做法速查

### 3.1 Wall 墙

正规做法：承重墙、非承重墙、内隔墙和房间边界优先使用 Wall。
类型职责：厚度、材料、功能层和墙体构造由 Wall Type 承担。
实例职责：底部/顶部标高、偏移、定位线、长度和局部约束由实例承担。
局部异形：连续墙体的斜顶、局部洞口或不规则顶部先用 Edit Profile。
屋面收口：需要随屋顶变化时使用墙顶附着关系。
装饰线脚：优先 Wall Sweep、Reveal、Profile 或受墙族。
玻璃立面：存在连续格网、竖梃、嵌板和门时改用 Curtain Wall。
禁止：用 Generic Model 或原位实体冒充普通墙。
检查：平面闭合、房间边界、墙连接、剖面顶底、门窗切洞和材料表达。

### 3.2 Floor 楼板

正规做法：常规楼板、阳台板、屋面板和平台优先使用 Floor。
边界职责：外轮廓和洞口由闭合草图控制，洞口优先用内环或正式开洞。
标高职责：基准标高与实例偏移控制板位，不用拖动几何猜高度。
类型职责：厚度、材料和构造层由 Floor Type 承担。
高差处理：先考虑分板、实例偏移、坡度箭头或形状编辑。
重复基础：预制台阶、看台单元和设备基础可用正确类别的 Loadable Family。
禁止：用白色实体遮洞，或用 Generic Model 承担结构板和房间上边界。
检查：草图闭合、边缘对齐、洞口、厚度、上下标高和剖面连接。

### 3.3 Roof 屋顶

正规做法：普通坡屋面优先 Footprint Roof。
路径型屋顶：沿轴线变化的屋面优先 Extrusion Roof。
坡度职责：坡度、坡向、檐口和厚度保留在屋顶系统中。
墙体关系：需要联动时让墙附着屋顶，不手工雕出相似斜面。
边缘构件：檐沟、封檐、檐口先检查 Roof Edge、Gutter、Sweep 和 Profile。
复杂曲面：先用 Mass 找形，再按面生成屋顶或幕墙，并清理接缝。
雨棚：跨项目复用的独立雨棚可用受面、受墙或非宿主 Loadable Family。
禁止：Mass 定型后仍把所有围护留成不可出图体量。
检查：坡向、排水逻辑、边界、墙顶连接、女儿墙和关键剖面。

### 3.4 Stair 楼梯

正规做法：正常疏散楼梯优先 Stair by Component 或 Stair by Sketch。
第一步：锁定起始标高、终止标高、总高和层高。
第二步：确定梯段数、平台位置、行走方向和洞口。
第三步：调整踏步数、踏面、踢面、宽度和支座。
第四步：检查自动生成或挂接的栏杆。
表现重点：先保留可用原生楼梯，再用局部细部补强，不雕每块踏步取代主楼梯。
层高变化：改层高后立即重查所有楼梯、平台、洞口和栏杆。
禁止：用一组孤立踏步几何冒充主疏散楼梯。
检查：上下层到达、净高、平台、方向、洞口、栏杆连续和剖面表达。

### 3.5 Railing 栏杆

正规做法：栏杆优先附着楼梯、楼板边缘、坡道或明确路径。
路径职责：主体边界变化时栏杆路径应可随动。
类型职责：扶手、顶扶手、竖梃图案、间距和高度由 Railing Type 管理。
截面职责：扶手与竖梃截面优先用 Profile Family。
重复面板：使用栏杆面板族或共享嵌套族，并验证统计需求。
方向检查：复制、镜像和翻转后检查扶手内外侧与起止收头。
禁止：沿楼梯边复制一排无宿主 Generic Model 代替栏杆系统。
检查：连续性、高度、转角、平台、上下收头、平剖可见性。

### 3.6 Curtain Wall 幕墙

正规做法：连续玻璃立面和规则分格使用 Curtain Wall 系统族。
建模顺序：墙类型 → 垂直/水平格网规则 → 竖梃类型 → 面板类型 → 门与例外面板。
固定距离：适合模数明确、总宽变化后仍维持标准间距的立面。
固定数量：适合总宽变化后保持格数和视觉节奏的立面。
面板职责：特殊几何、材质或信息使用 Curtain Panel Family。
门区处理：用 Curtain Wall Door 或对应面板族替换，不删除系统后手补玻璃。
例外策略：先完成典型 80%，再处理门区、转角、错层和收边 20%。
禁止：用若干普通玻璃墙拼出有明确格网规则的幕墙。
检查：典型格、边缘格、转角格、门区、竖梃、面板类型和立面节奏。

### 3.7 Curtain System 幕墙系统

适用：自由曲面或体量面上仍需要系统化面板和网格时使用 Curtain System。
前提：曲面几何由 Mass 或可靠面提供，面板逻辑可被规则描述。
正规做法：先稳定母体表面，再建立网格方向、分格密度和面板类型。
特殊单元：用自适应或幕墙面板族表达，先在小区域测试。
转换要求：检查面板接缝、边缘收口、法向、翻转和统计表现。
风险：每块面板都不同会导致系统失去批量控制优势。
不适用：不连续的单块玻璃、广告屏或没有格网关系的自由物件。
检查：曲率极值、边缘退化面板、转角、剖切线和三维连续性。

### 3.8 Door 门

正规做法：使用 Door 类别的墙宿主 Loadable Family。
宿主要求：门随墙移动并正确切割墙洞。
类型参数：宽、高、框型、材质、耐火等级等同型信息。
实例参数：Mark、实例备注、逐樘特殊信息。
图面表达：门扇和开启弧优先用 Symbolic Line，避免额外重几何。
方向控制：使用左右手和内外翻转，避免为每个开向复制一套族。
检查：典型墙厚、洞口、开启方向、平面符号、立面、标签和门表。
禁止：Generic Model、原位实体或手绘洞口冒充门。

### 3.9 Window 窗

正规做法：使用 Window 类别的墙宿主 Loadable Family。
宿主要求：窗随墙移动、切洞并响应墙厚。
类型参数：宽、高、框型、分格和主要材质。
实例参数：Mark、窗台高度、逐樘备注等按项目规则设置。
图面表达：控制粗略、中等、精细级别，不让不可见五金拖重模型。
幕墙边界：幕墙中的开启扇或门应使用幕墙面板体系，不混用普通墙宿主窗。
检查：窗台、洞口、内外方向、平立剖、标签和窗表。
禁止：在墙面贴玻璃几何代替窗族。

### 3.10 Furniture 家具

正规做法：优先使用轻量、非宿主、正确 Furniture 类别的成熟族。
建模深度：三维轮廓服务平面、立面和主要透视即可。
类型参数：标准尺寸、型号和材质。
实例参数：位置相关备注、编号或课程要求字段。
组合方式：会单独统计的子件用共享嵌套；仅造型组成用非共享嵌套。
房间布置：不要把整间家具塞入一个组合族，除非它确实是完全重复的标准单元。
检查：尺寸、碰撞、平面识别、房间归属、数量和模型性能。
禁止：导入不经清理的高面数产品模型填满项目。

### 3.11 Plumbing Fixtures 洁具

正规做法：使用 Plumbing Fixtures 类别的轻量成熟族。
宿主选择：按项目需要选择墙宿主、面宿主、地面/工作平面或非宿主族。
课程深度：正确类别、尺寸、安装位置和图面识别优先于完整连接器和施工五金。
参数策略：型号、尺寸和材质作为类型信息；编号与备注按实例需要设置。
重复卫浴：洁具本体保持正确族类别，空间组合可在真正一致时使用 Group。
检查：离墙距离、安装高度、平面净距、立面位置和明细表数量。
禁止：用二维符号代替需要进入平剖和统计的主要洁具。

### 3.12 重复标准构件：Loadable Family

适用：同一对象出现两次以上，或需要跨项目复用、独立编号、标签和统计。
第一步：定义类别、宿主、最少尺寸、信息字段和可见性要求。
第二步：选择正确 Family Template，不从错误类别勉强修改。
第三步：建立参照平面、原点、尺寸和参数骨架。
第四步：几何锁定参照平面，不锁临时几何边。
第五步：按粗略、中等、精细分配可见性和子类别。
第六步：flex 最小、典型、最大类型，再加载、标注和出表。
检查：可复用、可标注、可出表是完成定义，不只是三维好看。

### 3.13 规则重复：Array

适用：单一构件按固定数量、固定间距、总长或弧线规则重复。
项目前提：原对象先是正确类别、经过验证的单件族。
项目 Array：适合快速布置，先以小数量测试编辑、旋转、镜像和删除行为。
族内 Array：用参照平面控制第一件、最后一件和总体范围。
数量参数：设合理下限，避免零、负数或极端间距导致失败。
统计要求：可见重复不等于明细表可计数量，必须实际出表验证。
例外增多：开始逐件修改时，撤销阵列逻辑，改为独立实例或系统格网。
检查：数量、间距、宿主、类型、极值 flex 和 Schedule 计数。

### 3.14 复合重复：Group

适用：标准客房、卫生间核心、重复户型或多类别布置确实完全一致。
正规做法：先完成一套典型单元，清理临时元素，再创建 Model Group。
命名：名称包含用途、类型和版本，不使用默认编号名。
全局修改：编辑组定义，让所有实例同步。
单点例外：先判断是否应拆出该实例，不连续排除大量组内元素。
宿主风险：组内外复杂宿主、约束和相互依赖会使编辑脆弱。
不适用：各单元只看似相同，但墙洞、家具、面积或标注频繁不同。
检查：组实例数量、镜像、宿主、房间边界、例外和 warnings。

### 3.15 柱、电梯、坡道与主要空间

柱：使用正确 Architectural Column 或 Structural Column 类别，按任务深度选择。
柱：基准标高、顶部标高、偏移和轴网关系必须清楚。
电梯：井道优先由墙和楼板洞口形成，轿厢与门使用可靠族表达主要关系。
电梯：课程方案阶段不默认深化导轨、机房设备和制造细节。
坡道：常规无障碍坡道使用 Ramp、Floor 坡度或可维护系统组合，保留坡度和标高逻辑。
主要空间：用 Room 和闭合边界记录名称、编号和面积。
空间分隔：必要时使用 Room Separation Line，但不拿它掩盖本应闭合的墙体错误。
检查：柱网、井道贯通、板洞、坡度、平台、房间边界和面积。

## 4. 三类经验分级卡

### 4.1 分级使用规则

BEST PRACTICE 是行业稳定成熟方法，默认优先。
FAST WORKFLOW 是竞赛或课程作业的快速生产技巧，时间紧且风险可控时优先。
SPECIAL TRICK 是特殊高阶技巧，只有条件全部满足才使用。
每项技巧必须同时核对适用场景、优点、风险和不适用情况；高级感、复杂度和脚本化程度都不是采用理由。

### 4.2 BEST PRACTICE

| 经验 | 适用场景 | 优点 | 风险 | 不适用情况 |
| --- | --- | --- | --- | --- |
| 系统构件优先 | 主体墙、板、屋顶、楼梯、栏杆、幕墙和房间边界 | 保留正确类别、约束、连接、切割、标签和明细表 | 错误标高、类型或边界会传播到多个成果 | 真正唯一且无法由系统表达的非建筑系统艺术物件 |
| 参照平面先行的族 | 需要自制且会重复变化的门窗、家具、洁具或面板 | 尺寸由骨架驱动，几何不易漂移 | 约束过度、公式过多和极值未测会导致 flex 失败 | 一次性、无复用价值且不影响正式图纸的简单造型 |
| 样板视图反推 View Template | 多层平面、多立面、多剖面和多张 Sheet | 一次修改稳定传播，减少表达漂移 | 模板控制项不清会让局部修改看似无效 | 叙事目标完全不同的单张概念透视 |
| Schedule 作为模型 QA | 房间面积、门窗、家具、洁具和材料数据检查 | 暴露错误类别、空编号、边界错误和计数异常 | 过滤、共享嵌套和 Array 会产生错误数量 | 对象不需统计且任务只交单张概念图 |
| PDF 作为纸面验收物 | 所有正式图纸发布 | 暴露真实线宽、文字、裁剪、透明度和分页问题 | PDF 与 RVT 版本不同时形成伪验收 | 没有图纸输出要求的纯模型探索阶段 |

BEST PRACTICE 默认动作：系统构件先行；族逐步 flex；模板从打印验证过的样板视图建立；表格先找错后排版；PDF 在 100% 比例验收。

### 4.3 FAST WORKFLOW

| 经验 | 适用场景 | 优点 | 风险 | 不适用情况 |
| --- | --- | --- | --- | --- |
| 完整但朴素优先 | 一至两周课程作业或紧张竞赛 | 先确保总平、平立剖、三维和基础表完整 | 未映射评分项时可能漏掉核心特征 | 任务只评一张视觉展板且不要求 BIM 图纸 |
| 轻量成熟族替代全面自制 | 大量普通门窗、家具和洁具 | 节省建族时间并保持基本类别、宿主和统计 | 库族可能尺寸、类别、细节或重量不合适 | 评分重点要求独特构件，且库族不能表达 |
| 典型 80% 加例外 20% | 规则幕墙、重复楼层、标准房间和成组图纸 | 先固化多数规则，再处理转角和特殊单元 | 把真实差异硬塞进典型规则会产生隐蔽变体 | 每个单元都不同或例外已经成为多数 |
| 每日代表 PDF | 连续图纸生产阶段 | 提前发现线宽、裁剪、文字、表格和版本问题 | 总看同一张英雄图会漏掉其他图类 | 尚无任何可发布视图的最早体量探索 |
| 少量 QA Filter 清零 | 未编号门窗、未命名房间、异常面积和待检查对象 | 数据问题直接显现，便于快速扫查 | 参数空值和实例/类型混用会漏项 | 元素类别本身错误，此时先修类别 |

FAST WORKFLOW 启用规则：时间紧时优先完整交付，最后 20% 时间留给 QA 和发布；只自制关键三至五个类型；例外清楚命名；代表 PDF 轮换图类；Filter 保持单一语义。

### 4.4 SPECIAL TRICK

| 经验 | 适用场景 | 优点 | 风险 | 不适用情况 |
| --- | --- | --- | --- | --- |
| Mass 面生成系统构件 | 双曲、扭转或自由曲面外皮已完成体量找形 | 保留找形效率并可转成屋顶或幕墙 | 接缝、退化面板、法向、材料和剖切可能异常 | 普通平直墙、常规坡屋面或未稳定体量 |
| 共享嵌套族独立统计 | 父族内部子件必须单独计数、标签或出表 | 父族保持组合，子件仍可独立统计 | 可能重复计数并增加参数与对象复杂度 | 子件只服务造型或不需独立数据 |
| 参数化族内 Array | 桌腿、百叶、格栅等数量与总长关系确定 | 数量和间距随类型变化，减少复制误差 | 数量极值、公式边界和表格计数易失败 | 每件需独立移动、编号、改材质或布局不规则 |
| 经验证的 Dynamo/API 批处理 | 大批量编号、视图命名、参数写入或 QA 查询 | 减少重复劳动和漏改 | 错误范围或规则会高速污染模型 | 方案布局、审美决策、临期首次运行或不可回滚操作 |
| Section Box 轴测剖切 | 快速说明核心空间、竖向交通和构造关系 | 不删除模型即可形成清晰三维证据 | 剖切位置可能藏错，且三维不能替代正式剖面 | 需要精确尺寸、标高和二维制图证据 |

SPECIAL TRICK 启用规则：先证明常规方法不适用；再完成小样本、极值或计数测试；最后以平面、剖面、三维或 Schedule 的独立证据验收。
## 5. 建模深度：建筑课程方案设计

### 5.1 默认深度

模型服务建筑方案表达、平立剖成图、空间核查和基础 BIM 数据。
优先完成主体墙体、柱、楼板和屋顶。
优先完成门窗和主要开口。
优先完成楼梯、电梯、坡道和栏杆。
优先完成主要空间、房间名称、编号和面积。
优先完成主要家具和洁具，以证明尺度、使用和流线。
优先完成会进入正式图纸、标签、明细表或关键视图的构件。
优先级由构件影响的图纸数量、数据链和评分重要性决定。

### 5.2 主体必建内容

标高、轴网、项目单位和定位必须先建立。
外墙、主要内墙和房间边界必须闭合且标高正确。
各层楼板、主要板洞和屋面关系必须能在剖面解释。
屋顶应表达总体形式、坡度、檐口和与墙的关系。
门窗应表达基本位置、尺寸、开启或分格逻辑。
楼梯应连接正确楼层并形成连续竖向交通。
栏杆应随楼梯、平台和临空边界连续。
电梯井、主要洞口和核心筒应上下贯通。
主要空间应有可核查名称、编号和面积。
关键家具洁具应证明房间可用性，不追求产品级细节。

### 5.3 默认避免内容

默认避免施工级节点深化。
默认避免不可见五金、螺栓、铰链和制造构造。
默认避免极细构造层和课程成果不会表达的材料层级。
默认避免全套高精度家具、设备内部构造和复杂连接器。
默认避免不会进入任何成果的后台空间小物件。
默认避免为了渲染堆入高面数人物、树木和产品模型。
默认避免一次性复杂公式、深层嵌套和大量自适应构件。
默认避免在最后阶段新建未经测试的复杂族。

### 5.4 是否继续深化的判断

问该细节是否会进入指定平面、立面、剖面、表格或关键三维。
问该细节是否能证明主要设计特征或解决明显尺度问题。
问缺少该细节是否会让图纸错误，而不只是画面略显朴素。
问该细节是否会引入新的宿主、参数、性能或维护风险。
前三问均否时停止深化。
收益低于建模、检查和返工成本时停止深化。
任务书明确要求施工、结构或机电深度时，再扩大对应范围。

### 5.5 一至两周时间盒

第一阶段完成任务书到 Sheet 的映射、标高、轴网和样板视图。
第二阶段完成外壳、楼层、核心筒、楼梯和主要开口。
第三阶段放置门窗、幕墙、主要家具洁具和 Room。
第四阶段建立平立剖、Schedule、Tag、View Template 和 Sheet。
第五阶段只补强评分重点和少量英雄视图。
最后阶段冻结方案，只做 QA、输出、备份和确定性修复。
每天结束保留一个可打开、可导出、可回退的版本。

## 6. 成图系统：统一修改不炸

### 6.1 从图纸清单倒推模型

先列总平、各层平面、立面、剖面、三维、表格和局部图。
把每个任务书评分点映射到至少一个 Sheet 或视图证据。
为每张 Sheet 写清它要回答的唯一主问题。
确定每类视图的目标比例、阅读距离、细节级别和标注密度。
先建立一张样板平面、一张样板剖面和一张样板 Sheet。
模型顺序按影响范围排列：基准 → 围护与楼板 → 开口 → 交通 → 房间 → 图纸。
不为了填满模型而建不会进入成果的对象。

### 6.2 View Template

跨多数同类视图一致的设置必须进入 View Template。
至少按总平、建筑平面、立面、剖面和三维建立独立模板。
课程项目通常控制在五至八个清晰模板，避免模板泛滥。
模板名称包含专业/用途、视图类型、比例和发布状态。
从已验证的代表视图创建模板，不从空白视图猜设置。
优先控制比例、Detail Level、Visual Style、类别可见性和 Filter。
按需要控制 View Range、Crop、Scope Box、Phase、Link 和 Imported Categories。
创建新视图后立即套模板，不在出图前集中补救。
模板更新后抽查至少一张平面、一张剖面和一张立面。
受模板控制的参数不能靠单视图反复争抢；先识别控制层级。

### 6.3 Filter

同一类别内按参数条件显示、隐藏或突出对象时使用 Filter。
一条 Filter 只表达一个语义，例如未编号门或待检查房间。
先确认目标参数可被目标类别筛选。
QA Filter 可突出空 Mark、空房名、异常门宽、错误材质和阶段状态。
正式表达 Filter 应尽量放进 View Template，让同类视图一致。
颜色不能是唯一信息载体；配合线型、填充或文字说明。
临时借用 Comments 等字段时，交付前清理或转为明确标准字段。
Filter 漏项时先检查空值、拼写、实例/类型归属和类别，不先手工补色。

### 6.4 可见性控制层级

Object Styles 是项目图形基准。
View Template 是同类视图标准。
View Filter 是条件化标准。
单视图 Visibility/Graphics 是明确例外。
Override by Element 是最后手段。
族内子类别和可见性决定项目可以控制到什么层级。
大量元素级覆盖意味着标准失效，应回到类别、子类别、模板或 Filter 修复。
每个保留的单视图例外必须能解释用途。

### 6.5 Schedule

明细表是模型数据的读取与 QA 视图，不是手工文字表。
先确认对象类别、类型/实例参数和共享参数，再创建表。
一张表只回答数量、面积、编号、规格或某一 QA 问题。
房间表至少核对 Number、Name、Level 和 Area。
门表通常核对 Mark、Type Mark、Family and Type、Width、Height、Level、From/To Room。
窗表通常核对 Mark、Type Mark、Family and Type、Width、Height、Sill Height 和 Level。
实例 Mark 表示逐樘编号，Type Mark 表示型号，不混用。
先创建最少字段并观察空值、重复编号和漏项，再增加排序与格式。
发现异常先修模型、类别、边界或参数，不手改表格掩盖问题。
Array、共享嵌套和未放置族的计数必须通过小样本实测。
QA 表可不上 Sheet；正式表保持字段少、标题清、单位明。
表上 Sheet 后检查列宽、换行、分页、裁切和阅读顺序。

### 6.6 Tag 与模型数据链

正确链路是族/项目参数 → Tag Label → Schedule 字段 → 图纸核对。
标签不能凭空创建模型中不存在的数据。
需要跨族、Tag 和 Schedule 共用的字段采用统一共享参数。
不要在 Tag 旁手打规格或编号替代数据修复。
门窗标签与门窗表必须能双向抽查。
房间标签、房间表和平面边界必须互相一致。
Generic Annotation 用于重复二维说明，Detail Component 用于二维细部，不冒充模型对象。

### 6.7 Sheet

Sheet 是发布容器，View 是模型与注释容器。
先建立图纸清单、稳定图号和图名，再批量建 Sheet。
Title Block 使用正确类别的可载入族，不用普通文字边框代替。
项目名、图号、图名、日期和比例尽量由 Label 与参数读取。
先放主视图确定纸面重心，再放关联平立剖和表格。
相关视图尽量使用可比较比例；例外比例必须明确标注。
用统一留白和对齐组织版面，不让每个视图随机填满空白。
同一 View 不为不同 Sheet 任意改变比例；需要不同表达时复制合适视图并套模板。
工作视图、测试视图和发布视图在 Project Browser 中明确分开。

### 6.8 PDF 与 DWG 发布

PDF 是课程图纸的主要视觉验收物。
先导出代表平面和代表剖面，验证线宽、填充、透明度、阴影和文字。
最终按明确 Sheet 集批量导出，不混入草稿和测试图纸。
在 PDF 阅读器 100% 比例逐页检查，不用 Fit to Page 代替正确比例。
DWG 是交换格式，不是 BIM 主成果。
导出 DWG 前明确 Sheet/View、单位、图层映射、标题栏和模型空间需求。
先用少量视图验证 DWG 设置，再批量导出。
最终 RVT、PDF、DWG 和导出说明必须指向同一版本。

### 6.9 全局修改不炸的操作顺序

修改前保存可回退版本，并记录触发原因。
先确定变化属于方案、模型基准、系统类型、族类型、视图模板、Filter 还是 Sheet。
方案变化先回 Scheme，不在图纸层自行消化。
模型变化先在一个典型对象或副本验证。
类型变化先检查所有该类型实例和可能的特殊例外。
模板变化先检查受控项和受影响视图列表。
Filter 变化先检查类别、参数、空值和条件边界。
Group 变化先判断所有实例是否都应同步。
Array 变化先检查数量、宿主和统计。
修改后依次重查代表平面、剖面、立面、三维、Schedule 和 Sheet。
最后重新导出 PDF；旧成果标记 `OUTDATED`，不覆盖历史版本。

## 7. MCP 能力边界与专家操作协议

### 7.1 连接与执行事实

实际链路为 Mac 侧 Agent 经 SSH stdio 到 Windows MCP server，再到 Revit 进程内插件与 API。
npm server 必须运行在装有 Revit 的 Windows 主机，因为连接目标固定为同机 `localhost:8080`。
Revit 启动后必须人工打开 MCP Switch；工具可发现不代表 Revit socket 已开启。
单个 Revit 命令内部超时约 120 秒，调用应按顺序执行。
配置应禁用并行 Revit 工具调用；模型修改具有顺序依赖，不做并行写操作。
Revit 2021 使用匹配版本插件；插件、命令集和 Revit 主版本必须一致。

### 7.1.1 已验证的 Revit 2021 连接前检

目标为本工作区 Windows Revit 2021 时，先读取 [`references/revit-mcp-revit2021-validated.md`](revit-mcp-revit2021-validated.md)，并运行 `python3 tools/revit-mcp/scripts/smoke_revit_mcp.py`。

该脚本只读查询活动视图和模型统计；两项均成功后才允许任何 MCP 写操作。刚改过 MCP Settings 时必须完整重启 Revit，再重新 Open Server 和前检。前检失败是环境阻断，不以 `send_code_to_revit` 或其他写调用绕过。

### 7.2 26 个实际工具的定位

`say_hello`：只用于端到端连接冒烟，不产生建筑成果。
`get_current_view_info`：确认活动视图名称和类型，不替代视图内容检查。
`get_current_view_elements`：读取当前视图模型与注释元素，用于范围核对。
`get_selected_elements`：读取人工当前选择，用于定位和协同确认。
`ai_element_filter`：按类别、类型、可见性和空间范围查询元素。
`analyze_model_statistics`：读取元素、类型、族、视图、图纸、类别和标高统计。
`get_available_family_types`：查询项目现有类型 ID；创建前先调用，不写死 ElementId。
`create_level`：创建标高，并可生成楼层平面或天花平面。
`create_grid`：创建规则轴网，创建后仍须核对命名、间距和方向。
`create_line_based_element`：创建墙、梁、风管等线性构件；类别与类型必须明确。
`create_point_based_element`：创建门、窗、家具等点式构件；宿主与方向必须核对。
`create_surface_based_element`：创建楼板、天花或屋面；边界闭合、共面与标高必须核对。
`create_structural_framing_system`：创建梁框架系统；只在方案范围需要时使用。
`create_room`：在封闭边界内创建房间并写入名称、编号等信息。
`create_dimensions`：在支持标注的视图创建线性尺寸；引用与数值必须视觉确认。
`tag_all_rooms`：标注当前视图全部或指定房间；标签出现不证明房间边界正确。
`tag_all_walls`：标注当前视图墙体；仅在图纸确需且标签规则明确时使用。
`color_elements`：按类别和参数给当前视图着色，适合 QA 或分析，不改变模型正确性。
`operate_element`：支持选择、剖切框、着色、透明、删除、隐藏和隔离等操作，不支持移动。
`delete_element`：按 ElementId 删除；属于高风险操作，先确认范围与回退版本。
`send_code_to_revit`：动态编译执行 C#，属于优先级 5 的特殊 API 路径。
`export_room_data`：导出房间数据，用于面积和边界结果核对。
`get_material_quantities`：读取材料面积、体积和数量，结果依赖正确构件与材料。
`store_project_data`：把项目元数据写入 MCP server 本地 SQLite，不改变 Revit 模型正确性。
`store_room_data`：把房间元数据写入本地 SQLite，不替代 Revit 房间数据核对。
`query_stored_data`：查询本地 SQLite 保存的数据，不应被当作当前模型实时真相。

### 7.3 工具不存在时的判断

不存在已注册的通用 `modify_element` 工具。
`operate_element` 不支持 Move。
不存在通用 `create_view` 工具；基础楼层平面可随 `create_level` 创建。
没有工具不等于立刻使用纯几何 workaround。
先判断任务能否通过现有原生构件参数、类型和 Revit UI 完成。
确需批量移动、特殊视图或 API 操作时，`send_code_to_revit` 属于优先级 5，必须小样本验证。
不编造工具名，不假设空文件对应可调用能力。

### 7.4 每次创建的执行协议

第一步：从方案确认包提取对象类别、位置、尺寸、标高、宿主和类型需求。
第二步：按方法优先级确定正规 Revit 对象。
第三步：查询项目实际可用类型，不硬编码未知类型 ID。
第四步：用少量元素验证坐标、单位、标高、方向、宿主和边界。
第五步：检查返回的 ElementId、warnings 和创建数量。
第六步：用查询工具确认实际类别、类型、视图可见性和空间位置。
第七步：在 Revit UI 的平面、剖面或三维中视觉复核。
第八步：小样本正确后再扩大范围。
第九步：批量完成后用统计、Schedule 或 Filter 复核完整性。
第十步：导出关键平面、剖面和三维预览完成成果级检查。

### 7.5 坐标、单位与宿主

创建类工具的坐标、长度、厚度、高度和标高使用毫米。
坐标必须来自已批准定位，不从屏幕大致位置猜测。
创建墙前确认线段首尾、底标高、顶部约束、类型和高度。
创建楼板/屋面前确认外环闭合、内环方向、共面、类型和基准标高。
创建门窗前确认真实宿主墙 ElementId、族类型、插入点和翻转状态。
创建房间前确认边界闭合、房间点位于内部且编号不冲突。
任何宿主类构件创建后都要移动或检查宿主响应，不能只看初始位置。

### 7.6 `send_code_to_revit` 安全边界

仅在正规 Revit 方法明确、现有专用 tool 不足时使用。
动态代码不得用来绕过系统构件和族方法制造无语义几何。
运行前写明目标 ElementId、输入单位、事务模式和预期改变。
运行前列出不应改变的楼层、类别、类型和参数。
先在副本或孤立测试对象运行。
自动事务模式下不重复创建内部事务。
返回 success 后查询同一 ElementId，核对几何和参数变化。
删除、重建、批量替换和宿主变化属于高风险，临期默认不执行。

### 7.7 success 之后仍必须证明的事项

证明元素属于正确 Revit 类别。
证明实例使用正确类型。
证明标高和偏移正确。
证明宿主真实存在且关系正确。
证明墙、板、屋顶边界闭合并连接。
证明门窗实际切洞且方向正确。
证明楼梯连接上下层且栏杆连续。
证明 Room 有效、面积大于零且名称编号正确。
证明元素在该出现的平面、剖面、立面和三维中可见。
证明 Tag 与 Schedule 能读取正确数据。
证明批量数量与计划数量一致。
证明没有异常 warnings、重复元素或越界修改。

## 8. 常见翻车点与自检

### 8.1 与 revit-final-check 的协同边界

本 Skill 负责选择正规建模方法、建立可检查成果和执行过程内自检。
`revit-final-check` 负责最终系统性检查、缺陷分级、修复记录和发布判定。
使用本 Skill 不能替代最终检查。
最终检查发现问题后，回到本 Skill 的类别、宿主、约束、模板和参数规则修复根因。
每次修复必须重新检查受影响的平面、剖面、三维、Schedule 和 Sheet。
若 `revit-final-check` 尚不可用，仍执行本节完整清单并记录其缺失状态；不得声称已使用该 Skill。

### 8.2 模型不闭合

症状：房间无面积、剖面漏板、墙屋顶留缝、立面轮廓断裂。
先查：标高、约束、Room Boundary、墙连接、楼板边界和屋顶附着。
修复顺序：基准与约束 → 系统构件边界 → 局部轮廓 → 视图表达。
禁止修法：白色填充、遮挡实体、假面积文字或只在一张图补线。
复查：房间表、关键平面、关键剖面和 3D 剖切。

### 8.3 门窗不依附

症状：门窗浮在墙面、没有洞口、墙移动后不跟随、门窗表缺项。
先查：族类别、Family Template、宿主墙、开口切割、插入点和翻转。
修复：换用正确 Door/Window 墙宿主族，并在典型墙厚重新测试。
禁止修法：原位实体、Generic Model、手工墙洞加贴面几何。
复查：平面符号、立面、剖面、墙移动响应、Tag 和门窗表。

### 8.4 楼梯不连接

症状：梯段不到楼层、平台高度错、栏杆漂浮、净高不可解释。
先查：基准标高、顶标高、总高、踏步数、平台和洞口。
修复：从起终标高和总高重建逻辑，不从单块踏步外观修起。
禁止修法：移动孤立踏步凑齐高度，或用三维角度掩盖断接。
复查：上下层平面、纵剖面、三维、栏杆连续和洞口。

### 8.5 房间与面积错误

症状：Room Not Enclosed、面积为零、房名错层或面积与平面不符。
先查：墙体闭合、Room Bounding、分隔线、标高和房间点位置。
修复：先修边界和标高，再重新放置或更新 Room。
禁止修法：手写面积、在表格外计算后覆盖模型值。
复查：房间平面、房间表、颜色/QA Filter 和抽样尺寸。

### 8.6 标注丢失或数据脱节

症状：复制视图后标签少、编号不一致、手写文字与表格矛盾。
先查：复制方式、模板的 Annotation Category、标签类别和参数数据链。
修复：让 Tag 与 Schedule 读取同一模型/共享参数。
禁止修法：用普通文字填补缺失标签或手工改表。
复查：图中 Mark 能在表中找到，表中 Mark 能在图中找到。

### 8.7 Array 与共享嵌套计数异常

症状：视觉数量与 Schedule 数量不一致，或同一子件重复统计。
先查：父子族类别、共享设置、数组封装、表格过滤和实例放置方式。
修复：在小样本中比较独立实例、共享嵌套与非共享嵌套结果。
禁止修法：凭三维目测填写数量，或截取外部表替代模型表。
复查：每种计数机制至少抽查一组 ElementId 和表格行。

### 8.8 Group 变体失控

症状：同名组实例内容不同、排除项越来越多、宿主错误频发。
先查：各实例是否真的应完全一致，例外是否已经成为主要情况。
修复：真正全局变化编辑组；真实不同的实例拆组或改为更清晰策略。
禁止修法：不断排除元素维持“看起来还是同一组”。
复查：组实例数量、镜像、门窗宿主、房间边界和 warnings。

### 8.9 View Template 与 Filter 失控

症状：某张图改不动、同类图线型不同、Filter 漏项或误伤。
先查：模板受控参数、Filter 类别与字段、空值、类型/实例参数。
修复：回到模板和 Filter 规则，不逐元素重新覆盖。
禁止修法：为每张图复制一套略有差异的模板或大量 Override by Element。
复查：同类视图并排比较，并导出代表 PDF。

### 8.10 后期改模型炸图

症状：改一个类型后多张图、组实例、裁剪、标注或明细异常。
先查：类型影响范围、组/数组依赖、模板例外、深层嵌套和参数关联。
修复：回退到改前版本，在小范围验证后重新实施。
禁止修法：继续叠加局部覆盖直到表面恢复。
复查：代表平面、剖面、立面、三维、Schedule、Sheet 和最新 PDF。

### 8.11 模型性能下降

症状：打开、切视图、同步、导出或选择明显变慢。
先查：高面数导入、深层嵌套、复杂 Array、过多 In-Place、未清理链接和 entourage。
修复：替换轻量族、减少不可见细节、清理无用类型和测试元素。
禁止修法：删除正确系统构件换成一坨轻量假几何。
复查：典型视图打开、3D 导航、PDF 导出和模型统计。

### 8.12 Warnings 处理

每天处理新增 warnings，不留到最后集中爆发。
优先处理影响房间、宿主、约束、重复元素、标高和连接的问题。
概念阶段可保留的 warning 必须理解影响并记录理由。
不追求机械清零，也不把 warnings 当作无关提示全部忽略。
修复 warning 后确认没有引入新的几何或数据错误。

### 8.13 根因排查顺序

先查实际类别。
再查宿主关系。
再查关联标高与偏移。
再查类型与实例参数。
再查边界、约束和连接。
再查族内可见性与子类别。
再查 View Template 和 Filter。
再查 Schedule 字段与过滤。
最后才查单视图和逐元素覆盖。
修复模型根因后，再修视图表现。

### 8.14 过程自检节奏

建立标高轴网后，检查命名、高程、间距和生成视图。
完成墙板屋顶后，检查闭合、连接和关键剖面。
完成门窗后，检查宿主、洞口、方向、Tag 和 Schedule。
完成楼梯栏杆后，检查上下层、平台、洞口和连续性。
完成 Room 后，检查名称、编号、面积、边界和楼层。
完成模板后，抽查平面、立面、剖面和三维。
完成 Sheet 后，逐张导出代表 PDF。
任何大改后，重新走受影响范围的完整检查链。

## 9. 视觉验收与 本次图纸复核

### 9.1 视觉检查是强制证据

重要 Revit 工作完成后必须取得关键平面预览。
重要 Revit 工作完成后必须取得关键剖面预览。
重要 Revit 工作完成后必须取得 3D 预览。
三类预览必须来自同一模型版本。
预览必须覆盖主要设计特征、竖向交通和最易出错连接。
不得用只有三维的检查替代平面和剖面。
不得用只有查询 JSON 的检查替代视觉检查。
不得用 MCP `success`、元素计数或无 warning 单独判定完成。

### 9.2 关键平面检查

核对墙体位置、厚度、连接和房间闭合。
核对柱网、柱位、核心筒和主要洞口。
核对门窗基本位置、方向、编号和开洞。
核对楼梯起步、到达、平台、栏杆和板洞。
核对电梯井、轿厢/门基本关系和上下贯通。
核对主要家具洁具与功能、流线和尺度。
核对房间名称、编号、面积和边界。
核对轴号、尺寸、指北针、图名、比例和裁剪。

### 9.3 关键剖面检查

核对标高、层高、楼板厚度和上下关系。
核对墙顶、楼板边、屋顶和女儿墙连接。
核对楼梯总高、平台、净高、洞口和栏杆连续。
核对门窗高度、窗台、洞口和立面对应关系。
核对关键空间高度、体量特征和剖切叙事。
核对地形、首层、入口和室外高差。
核对没有漂浮、穿插、漏板或未闭合的主体构件。
核对剖切线强弱、远景层次、标高和文字可读性。

### 9.4 3D 预览检查

核对整体体量与 当前方案 体量参考一致。
核对屋顶、幕墙、主要开口和设计特征没有被误改。
核对楼层、核心筒、楼梯、电梯和主要洞口空间连续。
核对墙、板、屋顶之间没有明显裂缝、重叠或漂浮。
核对 Section Box 没有裁掉需要检查的关键问题。
核对高阶造型、In-Place、Mass 和 workaround 例外位置。
核对三维仅作为交叉证据，不替代技术图纸。

### 9.5 图纸视觉检查

在 PDF 100% 比例核对线宽和切投影层级。
核对文字、尺寸、标高、轴号和标签可读且不遮挡。
核对视图裁剪不切断关键标注。
核对表格列宽、换行、分页和标题。
核对图号、图名、比例、日期和版本。
核对输出页数与图纸清单一致。
核对无草稿视图、测试元素、调试字段和过期文字。
核对黑白或灰度输出仍能表达 Filter 信息。

### 9.6 本次图纸复核 检查包

提供当前 Revit 模型版本和对应 当前方案 方案版本。
提供关键平面、关键剖面和 3D 预览。
提供图纸索引与成果清单。
提供自检范围和检查日期。
提供已修复问题、复查证据和仍存风险。
提供低优先级建模方法例外记录。
提供版本变化与返工影响说明。
明确请用户检查建筑忠实度、图纸完整性和主要设计特征。

### 9.7 本次图纸复核 结果处理

用户指出模型或制图错误时，记录问题、修复根因、重新导出并复查。
用户指出方案问题时，停止局部美化，返回 方案深化能力。
不得在 本次图纸复核 中自行改变空间关系来绕过问题。
不得用渲染后期、遮挡或图纸覆盖掩盖几何错误。
只有用户明确通过 本次图纸复核，才冻结可视化输入模型。
通过后记录确认版本，附导出坐标、单位、格式和材质状态。

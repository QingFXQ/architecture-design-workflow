# Revit模型整理与故障处理

## 入口与范围

先查[工程资产入口](../../workflows/ENGINEERING_ASSET_WORKFLOW.md)，只读取本次任务相关方法。构件怎么制作见[revit-expert](../revit-expert/SKILL.md)；本技能处理已有模型表达、语义核对与软件故障，不自行改变获准设计。

- 首次接手确认文档、未保存状态、版本和相关构件；建立可复用基线。后续同版只查受影响范围。
- 首次实际写入前准备恢复点，区分磁盘备份与内存未保存改动。只读查询／导出不要求为备份强制保存。
- 整理范围由当前任务决定。52项[检查表](checklists/revit-hardening-checklist.csv)是可筛选参考，不是每轮全部填写的门槛；未涉及项标不适用，不扩张任务。
- 已有授权的常规整理连续完成，不因本文另增人工Gate。

## 一、先判断对象实际承担什么

| 线索 | 正确用法 | 不能直接推出 |
| --- | --- | --- |
| 墙有窗、Room引用次数 | 结合墙两侧空间、围护位置、阶段和同版平剖三维判断 | 有窗必为外墙；零引用就是可删 |
| 墙短、矮、共线、围成小矩形 | 核女儿墙、井壁、洞口反坎、收口和历史用途 | 一律试验件或残段 |
| 同层同端点 | 作为疑似重复，进一步核类型、厚度、高度、偏移、阶段、实体 | 可以直接删多余墙 |
| LevelId／原生Stairs计数 | 联合底顶约束、包围盒、相关对象及真实图面查跨层构件 | 只服务一个楼层；Stairs为0就是没有楼梯 |
| 零面积Room | 查单位、插入位置、边界、阶段、重复房间和计算时机 | 一定有墙缝 |
| 数量不变、警告为0 | 辅助核对变更是否符合计划 | 设计、结构与图纸已正确 |

不复制过时图册的房名／数量去制造Room。当前设计决定＋同版模型与图纸共同解释差异；不能靠改名赋予构造或防火性能。

## 二、只做相关整理

### 图形

按[图形层级](references/graphic-hierarchy-revit.md)区分剖切、投影、辅助信息。线宽号只是项目和比例下的设置，不是固定毫米值；对象样式、模板、过滤器、单元素覆盖及族表达一起判断。

需要承重剖切实心表达时，先识别真实承重身份和是否被剖切；不把所有墙、玻璃和门窗统一涂黑。先做一个代表视图／PDF小样，再扩大应用。

### 墙型

先明确实际内外关系及墙体构造，再决定复制类型、更换类型或仅改语义。更换共享类型前列出受影响实例，避免以一个类型对象冒充只影响一段墙。类型名、材料层、厚度和性能分别核实。

### 疑似孤立／重复构件

结合用途、连接、宿主插入物、依赖、阶段与实体判别。没有重复不说明其他对象合理；存在重复也不授权删除全部同端点构件。删除返回的关联对象应与预期比对。

## 三、软件操作纪律

详细方法见[API现场笔记](references/revit-api-field-notes.md)，不要把本地数值当通用限制。

- API长度英尺；输入米／毫米显式转换，函数分别命名MToFt／MmToFt。
- 调用前核包装器事务归属。auto已经开事务时不嵌套顶层Transaction；none可用于只读或受控显式事务，依当前封装确认。
- 显式事务先Start并核Started，再设置失败处理选项；只有Committed是已提交。Pending不是成功，不继续写入或宣称已保存。
- SetForcedModalHandling(false)只改变失败处理方式，不能消除失败或保证无对话框。使用已验证的事务级失败预处理，未知失败记录并回滚，不全局吞掉全部警告。
- 未验证操作先最小样本，后按风险、耗时与载荷分批；3构件／20房间是过去特定环境的保守值，不强制所有项目照搬。
- 超时后一次有界探活，结合当前UI、进程及新日志诊断；无响应不唯一等于模态框，响应恢复也不证明前次写入成功。回读目标后决定是否重试。
- 保持单写入者，不盲重放、不强杀或自动关闭用户进程。端口从当前配置／日志核实，不固定8080／8088，不默认只能人工操作。

## 四、完成依据

只核当前变更涉及的内容：目标、实际对象／参数、关联门窗／房间／视图、异常与保存边界。重要几何或表达修改必须看相关平面、关键剖面与三维／纸面输出，不能只看API回包。

独立回读可合并为相关对象的一次查询，不每个对象全量扫描；完整哈希仅在恢复点、正式版本交接等确有需要时做。若文件被占用如实记未核，不不断重试。

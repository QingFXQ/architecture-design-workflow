# SketchUp MCP 通用安装部署提示词

用途：交给能够操作Windows本机的Agent，在**用户明确要求实际部署时**使用。阅读本文件、收录到仓库或讨论工作流，不等于要求立即安装。

适用于Codex、WorkBuddy及其他支持本地MCP的执行器；客户端配置按其当前官方文档处理。本提示词不绑定某个SU年份、电脑路径或固定发布版本。

---

## 可直接复制的提示词

请在当前Windows本机部署SketchUp建筑设计自动化连接环境。先检查实际环境，再选择兼容版本、安装、配置和真实验收；不要只交一份安装教程，也不要把准备完成写成连接成功。

### 1. 目标与范围

- 连接**本机SketchUp Desktop当前模型**，可查询、建模、截图、保存和导出。
- SketchUp与Blender两条路径都保留；由项目和使用者选择，不卸载或替换Blender，不强制模型反复转换。
- 保留Python、PowerShell和CLI操作能力，支持Agent生成、保存、调用SketchUp Ruby API脚本，不局限于MCP自带的基础建模工具。
- 仅使用Windows本机链路，不引入WSL、虚拟机、SSH、远程服务器或公网端口。
- 不假设SketchUp具有Blender式无界面后台建模模式；Ruby API建模依赖真实桌面进程及其事件循环。
- 不购买许可证、绕过授权或自动下载SketchUp本体。若本机没有可用SketchUp Desktop，完成可独立进行的工具选型、包与配置准备，明确标记缺少宿主软件；不伪造插件安装和实机测试通过。

### 2. 首选与回退

首选上游：https://github.com/2ez4gcx/sketchup-mcp

先阅读执行当时最新README、Releases、版本要求、已知问题和许可。选择**当前稳定且与本机兼容**的版本，记录release、源码提交、包来源及校验值。排除草稿和预发行版；不要把仓库里旧的固定版本或URL中的`latest`当作永远不变的版本号。

服务器与Ruby Bridge必须使用相配套的版本。若最新稳定版不支持本机版本，依据兼容证据选择仍可用的稳定版并说明原因；不要为了追新破坏现有环境。

只有首选在当前客户端或SU上出现可复现的不兼容、且合理诊断后仍不能使用，才评估：https://github.com/Son-The-SUN/sketchup-mcp

回退前重新核该项目的真实状态、版本、许可、Windows兼容和功能；未核实不得直接称为更稳定。试用回退桥前停用本次安装的首选桥，保留恢复路径，不同时启动多个争用同一端口或控制同一模型的桥。

### 3. 环境检查与备份

先只读检查：

1. Windows、实际SU可执行文件和版本、是否为Desktop、授权／启动可用性、当前是否有未保存模型。文件夹残留不算软件已安装。
2. 当前MCP客户端及其版本、配置位置和可用传输；明确客户端与SU均在本机。
3. Node.js、Python、PowerShell、CLI与必要依赖的可用路径及版本；只补实际需要的依赖，不替换已有可用运行时。
4. 已有SU扩展、MCP服务名、监听端口及对应进程。识别Blender和已有SU桥，不能只凭端口能连就认定对端是SU。
5. 目标客户端配置及即将更改的扩展文件是否已有内容。

修改前做带时间戳的配置／扩展备份，并记录恢复方式。只合并所需条目，保留其他MCP服务、凭据、用户设置和已有工具。输出中不打印密钥。

不要通过关闭用户软件、强杀进程、清空模型、降低全局扩展安全策略来制造“干净环境”。现有未保存工作不能丢失。

### 4. 安装与连接

1. 获取配套稳定版服务器和Ruby Bridge，优先使用上游正式发布包；保留许可。校验下载内容，记录来源和版本。
2. 按最新上游安装方法部署到**选定的SU版本**。不要未经说明更新所有SU版本或覆盖其他桥；需要重启时先保护当前工作。
3. 为SU选择空闲loopback端口，建议使用独立于Blender常见端口的值，例如19876；该值只是建议，必须现场核查。客户端与Ruby Bridge的端口一致，不暴露到局域网或公网。
4. 按**当前客户端官方格式**配置本地MCP。Codex写其实际使用的MCP配置；其他客户端使用各自格式，不把`mcpServers` JSON直接塞进所有客户端。使用稳定绝对路径并正确处理中文、空格与转义。
5. 如果上游发布包主要面向Claude，检查其是否同时提供标准MCP服务器启动入口；按文档由通用客户端启动，不因文件扩展名就假定仅能用于Claude。
6. 客户端调用超时与桥接超时协调配置；不依赖无限等待。启动后核版本、工具发现、`ping`与当前模型身份。
7. 不为执行本任务新增周期自动任务、开机启动项或多余常驻服务。需持久运行的只是正常SU插件及客户端配置；是否改变桥的自动启动行为应明确记录。

已有安装可用时优先核验／复用，避免重复安装和重复注册。普通且已授权的配置操作连续完成，不逐条向用户请求确认；真正涉及授权、必要GUI操作或未保存工作时再说明所需动作。

### 5. 建筑设计脚本链

实现并演示以下分工：

- **Python**：维护外部参数与JSON/CSV，校验输入，生成Ruby脚本或调用任务入口；不直接把外部网格包装成已验证的SU内部建模。
- **Ruby API**：在SU内部创建和修改实际几何、ComponentDefinition／ComponentInstance、群组、Tag、材质、视图及文件导出。
- **PowerShell**：组织任务路径、参数生成、调用、结果收集和日志；仅在用户额外要求时设置定时任务。
- **MCP／CLI**：连接客户端与SU，调用所需脚本并返回可判断的结果；协议输出与诊断日志分开。

建筑用途至少覆盖可继续扩展的墙体、楼板、屋顶、门窗、柱网、幕墙与楼梯。优先将常用参数组织为少量可复用函数／脚本，不为每种构件另建Agent或复杂服务。清楚说明哪些能力已经演示、哪些只是通过Ruby API可扩展，不能只因有`run_ruby`就宣称所有建筑功能已经完成。

建模要求：

1. 单位明确。外部建筑参数可使用米；桥接工具若使用毫米则转换；Ruby API内部长度按SU约定处理。输出统一带单位，不直接混用米、毫米和英寸。
2. 用命名群组隔离几何；Tag用于显示管理，不能代替群组避免几何粘连。组件及对象带稳定逻辑标识，区分实例和定义。
3. 重复窗、柱、幕墙单元等优先共享ComponentDefinition、批量创建ComponentInstance，不逐个发送大量MCP请求；不同规格使用不同定义。
4. 墙、板、屋面、门窗和梯段应形成真实可编辑几何。门窗的洞口不能仅靠窗片遮墙假装完成；切割能力与宿主关系要明确验证。
5. 保持概念／方案深度，不提前复杂化为完整BIM系统、精细家具统计或结构计算。楼梯／结构示意的建模成功不等于规范与受力验算。
6. 每个批次使用合适的SU operation，错误时回滚。脚本不嵌入与桥接层冲突的嵌套operation；根据上游对`run_ruby`的包装方式确定事务归属。
7. 重复运行按逻辑标识更新或重建**该任务自己的对象范围**；不追加一套新建筑，也不清空整个模型。参数不变时数量不增，参数变化时正确更新。
8. 超时后先查询模型和对象状态，确认是否已执行；不盲目重发建模、保存或导出。长任务拆成可回读批次，不用无限循环冻结SU。

### 6. 真实验收

在隔离的测试模型与测试输出目录进行，保护用户原文件。不要在最终建筑模型上做试验。若当前进程有未保存工作，不擅自切换或关闭它。

验收至少包含：

| 测试 | 操作与通过依据 |
| --- | --- |
| MCP连通性 | 初始化、工具列表、版本、ping与模型查询均成功；确认是目标SU而非其他桥 |
| 矩形建筑 | 使用明确参数生成简化建筑，例如10×8m、层高3.6m，包含有厚度墙体、楼板、屋顶和至少一处门洞；回读尺寸与包围盒 |
| 十组重复窗 | 创建10个同规格窗组件实例，共享同一ComponentDefinition，位置／方向正确，检查墙洞表达，不仅统计实例数量 |
| 材质与Tag | 指定墙／玻璃等基本材质与命名Tag，查询归属并在截图核对，避免每次重跑复制同名材料 |
| 截图检查 | 从真实SU视口导出轴测及必要局部，实际打开检查尺度、开口、重叠与缺件；不能只检查文件存在 |
| 保存与重开 | 另存测试SKP，检查路径与文件；在保护当前工作的前提下重开测试文件，核对象、定义和材料仍存在 |
| 幂等 | 相同参数再运行一次，比较任务对象／窗实例／定义／材料数量，无重复构件；再改一个参数验证确实更新，不能仅因对象存在就全部跳过 |
| 导出 | 导出一张PNG和至少一种本机可用的三维交换格式，记录格式／单位／坐标；导出器缺失或许可不支持要如实报告 |

上述是一次部署的核心演示，不要求做一栋完整复杂建筑。柱网、幕墙、楼梯等额外示例按实际准备情况标记，不为了列表全绿虚构验证。

离线MCP工具发现、模拟桥测试与真实SU测试必须分开记录。截图返回成功、对象数量正常或文件非空都不能单独代表验收通过。缺少SU／许可证／扩展启用等实质条件时，交付已完成准备和具体缺口，不能报告“全通过”。

### 7. 最终交付

请交付实际路径与简明说明：

1. 安装状态：SU、客户端、服务器、Ruby Bridge、依赖和端口，列明实际版本与尚未完成项。
2. 配置位置、备份位置、启动／停止及卸载／恢复方法；不泄露密钥。
3. 可复用的参数JSON／CSV示例、Python生成入口、Ruby建模脚本、PowerShell任务入口；参数路径相对工程根组织，不硬编码个人电脑目录。
4. 测试SKP、真实截图、导出文件及逐项验收结果，区分通过、失败、未测与原因。
5. 日常用法：打开SU及目标模型→确认桥／模型身份→改参数→执行任务→截图回读→保存／导出。给出一条可直接运行的Windows示例命令。

不要把这次部署扩张为其他工作流重构，也不要自动提交、推送仓库或安装无关插件。获得本任务部署授权后持续完成可逆且必要的步骤；出现真正阻断时说明具体原因和最小所需动作。

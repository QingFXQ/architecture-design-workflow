# AutoCAD MCP 通用安装部署提示词

用途：交给可操作Windows本机的Agent，在**明确要求部署时**使用。阅读、收录或讨论本文件不触发安装。适用于Codex及其他支持本地MCP的客户端；配置按执行时的官方文档适配，不硬编码某台电脑。

AutoCAD可作为独立的建筑制图路线，Revit仍保留。按使用者、项目与交付需要选择，不强制先做RVT，不把CAD仅当作Revit导出格式，也不把普通DWG冒充BIM。

---

## 可直接复制的提示词

请在当前Windows本机部署建筑设计用AutoCAD自动化工作流。先核查上游与实际环境，再安装、配置、执行可复现的真实测试并交付使用方法。不要只停在方案说明，也不要将缺少宿主软件的准备工作报告成部署成功。

### 1. 项目与版本核查

首选项目：https://github.com/U-C4N/Autocad-MCP

先阅读执行当时最新README、Releases、安装说明、依赖、许可、后端兼容性和已知问题。确认该仓库与所发布Python包、命令入口的对应关系，选当前稳定且兼容的版本，记录版本／提交、包来源和校验依据。排除预发行／草稿，明确固定最终采用版本，不长期依赖浮动`latest`。

用户曾提供的候选安装形式如下，**仅为待重新核实的历史示例，不证明该版本、extras或命令在当前环境可用**：

```powershell
codex mcp add autocad -- uvx --from "autocad-mcp-pro[com,pdf,office]==1.7.0" autocad-mcp
```

执行前检查当前稳定版、包extras、入口以及`codex mcp add --help`。其他客户端按其原生格式注册，不照搬Codex命令。依赖以实际任务为准，不为包含`office`而擅自安装Microsoft Office等无关桌面软件。

### 2. 环境检查与范围

只读检查并报告：

1. AutoCAD是否真实安装且可启动、具体版本、完整路径、完整版还是LT；残留文件夹不能证明安装可用。
2. 当前AutoCAD进程、活动DWG、未保存状态、既有插件、自动化桥和所用端口／IPC目录。
3. 当前MCP客户端及版本、实际配置位置、已有服务；Codex按当时官方说明及CLI帮助核查配置格式。
4. Python、uv／uvx、Git、PowerShell及相关CLI的实际位置和版本；确认解释器架构及后端兼容，不污染不相关全局Python环境。
5. COM、AutoLISP、脚本、Core Console各自是否适用于该版本／产品，而不是仅查命令是否在PATH。

优先复用已有环境。不要关闭或强杀用户软件，不清空现有DWG，不覆盖配置或重装其他已工作的插件。修改前备份客户端配置及涉及的已有插件文件，保留其他MCP服务和用户参数，不在输出中展示凭据。

只运行Windows本机链路，不引入WSL、远程服务或公网接口。不购买许可证、不绕过授权、不自动安装AutoCAD本体。本机没有AutoCAD或授权不可用时，继续完成独立DXF能力、资料／配置准备与可运行测试，明确哪些实机项未测及原因。

### 3. 后端选择与MCP配置

- **完整版AutoCAD**：优先评估上游COM Backend，在当前版本验证读取、写入、保存和导出。
- **AutoCAD LT**：不得强行使用完整版COM路径；核该版本实际自动化能力，评估https://github.com/puran-water/autocad-mcp 的AutoLISP／File IPC方案，阅读最新资料后再采用。不能默认所有LT版本都支持所需AutoLISP或该桥。
- 若首选与本机不兼容，给出可复现原因和可行后端，再实施兼容方案；不要只凭仓库宣传切换。
- 同一图纸一个写入者；不并行启动争用端口、IPC文件或控制同一文档的桥。多个AutoCAD实例时必须识别目标文档，不凭COM连接成功就认定控制了正确实例。

首选实现若经当前文档确认支持，采用以下设置；名称、格式和值必须现场核实：

| 配置意图 | 候选配置／处理 |
| --- | --- |
| 减少工具上下文 | `DISCOVERY_MODE=search`，验证搜索与按需调用确实工作 |
| 建筑常用能力 | 启用`core,arch`专项包，核实际启用字段与发现结果，不把字符串当作已生效 |
| 文件范围 | `ALLOWED_PATHS`限定独立CAD工程根，按上游要求的路径列表格式填写；核其实际保护哪些工具，不当作整个进程的万能隔离 |
| 后端 | 显式选本机兼容后端，记录为何采用COM或File IPC |
| 文件与出图 | 保留本工程内必要的读写、截图和PDF；不要为工具发现成功开放全部磁盘 |
| 命令保护 | 不启用危险命令绕过选项；只在已授权测试目录使用必要建模／保存命令 |

配置新增条目时保留已有MCP服务器。启动后核后端、版本、工具发现／搜索、目标文档及连接错误。客户端超时与后端任务时长协调，不用无限等待掩盖阻塞。

### 4. 独立工程目录

在用户工作区内选择新的CAD工程目录，已有同名目录则先检查并复用合理结构，不覆盖内容。例如：

```text
CADArch/
├── scripts/       # Python、PowerShell、SCR
├── lisp/          # AutoLISP
├── blocks/        # 可复用图块
├── templates/     # DWT与出图样式
├── configs/       # 参数JSON/CSV与非敏感配置
├── drawings/      # 工作图纸
├── exports/       # PDF、PNG、交换文件
├── tests/         # 隔离的验收工程与结果
└── backups/       # 修改已有图纸时的恢复副本
```

自动化只操作指定工程范围。用户已有DWG修改前备份，备份覆盖的是磁盘版还是内存另存版应说明；不能用磁盘复制冒充未保存改动的恢复点。不要为只读查询反复备份整套项目。

### 5. 保留四种操作方式

1. **MCP**：查询、交互编辑、文档状态与实体检查；优先少量明确调用和可回读的批次。
2. **Python**：参数、JSON/CSV、批量几何与数据处理；安装并验证`ezdxf`，生成真正的独立DXF。完整版COM需要时安装并验证`pywin32`，不把安装包成功当作COM已连接。
3. **AutoLISP**：在CAD内部批量建图／修改、自定义命令及复用图块；按当前产品与版本验证加载和执行。
4. **PowerShell／CLI／SCR**：组织路径、依赖、任务调用、批处理与输出记录；保存可重跑入口，不擅自设置定时任务或开机任务。

若存在`accoreconsole.exe`，记录实际版本与路径，在隔离测试文件上核它可加载的插件／脚本及后台出图能力。不能认为GUI中可用的COM／MCP／截图工具在Core Console也可用；没有Core Console时不伪造无界面AutoCAD能力。

DXF不是DWG。读取／生成DXF不等于支持DWG转换；DWG保存、版本和重新打开需由实际可用且经验证的CAD／转换工具完成。PDF输出同样要验证实际页面内容。

### 6. 建筑设计制作方法

建立少量可复用的参数化脚本，允许通过JSON／CSV修改建筑尺寸、轴网柱距、墙厚、门窗位置、图层与基本标注参数。按任务自动选择MCP、Python、AutoLISP、SCR或经验证的Core Console，不逐个发送数百次MCP调用创建重复图元。

重点覆盖：

- 建筑定位与轴网、墙体和柱、门窗与楼梯的平面表达。
- 平面／立面的重复构件，Block、块属性、阵列与共享定义复用；避免每个同规格窗复制一套无关联散线。
- 图层、线宽、线型、文字样式、尺寸样式与填充；按任务书／项目标准配置，不强套某套课程字体和线宽。
- 房间闭合轮廓与面积统计，标明单位；不能用文字标签或未闭合线的包围盒冒充净面积。
- 图框、模型空间／布局／视口、实际打印比例、PDF批量输出；尊重工程既有CTB／STB体系，不无故转换。
- DWG／DXF的保存、实体与块引用检查、字体／线型／外参及导出缺失检查。

脚本要求：

1. 输入及输出明确单位；核模型单位、坐标系／UCS、原点、块比例和标注比例，避免仅凭屏幕观感。
2. 按图层／块名／属性或其他稳定标识限定本任务对象，重复运行更新相应范围；不全图删除，也不不断叠加新实体。
3. 多阶段操作确认命令已结束、图纸可响应，再执行下一批；不向尚未完成的交互命令盲目发送输入。
4. 可撤销编辑与打开／保存／发布操作分别处理。超时先查当前图纸和输出，避免重放已完成操作。
5. 实体数据与实际图面一起核验；图层正确不代表尺寸正确，保存成功不代表布局与PDF完整。

### 7. 实际验收

用新建隔离测试文件，不直接修改用户原图。以简化建筑局部证明链路，不扩展成完整复杂施工图。

| 项 | 实际操作与通过依据 |
| --- | --- |
| A MCP连接 | 搜索／发现必要工具，读取目标图纸名称、后端与图层；确认连接到预期实例 |
| B 建筑绘制 | 在新图中生成有明确参数的矩形建筑轮廓、墙体、门窗、柱网和尺寸标注；核几何坐标、墙厚、单位与标注值 |
| C 重复图块 | 一个标准窗块定义批量插入至少20个实例，核共享定义、实际坐标、数量、比例／方向及图层 |
| D 独立DXF | Python＋ezdxf在不调用GUI建图的情况下生成独立DXF，再读回检查；可用时在CAD中打开核对 |
| E 保存与发布 | 另存真实DWG，保护当前工作后重新打开，核实体／块；输出PDF并渲染查看页面，检查图框、视口、比例和文字 |
| F 批处理 | 实测当前支持的AutoLISP、SCR及PowerShell调用；Core Console存在且可用时另测后台任务，逐项写结果 |
| G 图面检查 | 获取真实截图／PDF预览并打开观察，与实体结果核对缺件、重叠、图层、重复对象、字体与导出范围 |
| H 重复执行 | 同参数再运行，任务实体／块实例不增加；改一个参数后能正确更新，不是检测到旧对象就全部跳过 |

根据实际后端填写通过／失败／未测／不支持及原因，不用离线工具列表或模拟后端冒充AutoCAD实测。缺少宿主软件时D可独立完成，A/B/C/E及相应GUI项仍须如实标未测。

### 8. 最终交付与日常使用

提供简明报告及实际路径：

- AutoCAD版本／完整版或LT／位置、客户端版本、服务器与后端、连接状态、端口或IPC范围。
- 配置及备份位置、恢复／停止／卸载方法；不泄露凭据。
- Python环境、ezdxf／COM、AutoLISP、SCR、PowerShell及Core Console的逐项状态。
- 参数文件、可重跑脚本、测试DWG／DXF、窗块、截图、PDF和验收结果。
- 日常入口：打开目标CAD工程→确认文档／后端→修改JSON/CSV→执行任务→查看实体及图面→保存／发布。给出适用于本机的简短Windows命令示例。
- 尚未解决的具体问题和最小所需动作；没有软件／授权时明确准备完成的边界。

获得本任务实际部署授权后连续完成必要且可恢复的步骤，出现可修复错误就诊断处理，不每步询问“是否继续”。仅在必要授权、无法取得的输入、用户未保存工作或确实无法自动完成的GUI操作阻断时求助。

不要顺带安装无关软件、修改其他项目、重构整个工作流或自动推送仓库。

## 记录与使用边界

本提示词由用户提供的部署要求通用化整理。仓库收录时**没有执行AutoCAD环境探测、包安装、MCP注册或实机测试**；不对用户所给版本及项目能力作“当前已验证”背书。未来执行必须重新核上游及当前客户端文档。

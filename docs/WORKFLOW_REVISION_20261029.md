# 2026-10-29：图书馆实战后的工作流修订

依据本对话的真实使用反馈、WB交付摘要、仓库已有技能和工程样板整理。目标是让当前Agent自己理解资料、实际做图和检查，不再让用户反复纠正组织方式与机械错误。

## 当前主线

Blender／SU概念与截图预览 → 同模型方案深化 → 核场地、主要尺寸与任务书 → Revit／CAD标准建筑图 → Blender立面、亮点与表现 → 优秀排版参考和纸面预案 → 按版面制作分析图 → 同版汇总、最终排版与PDF。

详细操作在[主流程](../workflows/PIPELINE_WORKFLOW.md)、[制图生产](../workflows/DRAWING_PRODUCTION_WORKFLOW.md)和[表达交付](../workflows/PRESENTATION_WORKFLOW.md)。全程允许设计回环，不把软件阶段写成禁止条件。

## 改了什么

| 反馈 | 已落实的改变 |
| --- | --- |
| 六角色、人工Gate没实际用上 | 单主控连续执行；agents改为能力入口；旧组织／部署原文标历史，不再阻断实际工作 |
| 纯AI概念失真、不可控 | 概念就读真实CAD／PDF／图片，在Blender／SU建可编辑模型、截图和按需AI预览 |
| 方案需要比Revit／CAD更灵活 | 方案阶段延续工作模型；确定后才核尺寸场地和任务书，转工程图 |
| 工程skill没有用起来 | 按问题取操作卡和工程样板；先做典型区／代表图，再批量扩展；对象回读与实际看整图并行 |
| Revit经验长而难调用 | 保留原工程内容，大篇幅方法／复核集合移到references；入口简化，按需读取 |
| CAD路线也要能独立完成 | 保留CAD技能、参数化DXF样例，补工程经验；真实DWG／宿主能力与离线能力分开 |
| 家具和数量消耗太多时间 | 功能、结构、流线、空间和图面优先；家具整齐真实、不过度相交／穿墙／堵路即可 |
| 跨层、门洞、楼梯和剖面反复错 | 整理单位、宿主、Z范围、失败处理、切线与深度、同版输出等真实症状和方法 |
| Blender不只是末端渲染 | 全程可编辑；工程导出后深化立面与场地，变化同步受影响图纸 |
| 排版机械、字体小、植物假 | 原始图板参考→纸面预案→分析图→最终PDF；图内字体及图名按项目，图底和装饰一起设计 |
| 分析图会塞不下 | 先按任务书必交图算板面，剩余位置决定分析图；爆炸图实际分层展开 |
| 每次踩坑后还会重复 | 新增技能维护闭环，修原条目、样板与检索词，区分项目规则与通用经验 |

## 保留与后续使用

现有技能、研究资料、工程样板、部署提示词和案例库保留。改写前的角色／概念方案／工程入口原文在[历史目录](history/pre-20261029/README.md)，不作为当前指令。RAG、技能和排版参考分别按问题调用，不要求每阶段写卡、全量体检或新增交接包。

使用中出现新错误时，执行[技能维护](../workflows/SKILL_MAINTENANCE_WORKFLOW.md)修原条目并补真实证据。缺原生RFA／RVT／DWT／DWG资产或宿主实测时如实说明，不靠资料数量宣称工程能力完成。

本机新增模型、缓存和临时数据统一./local/resources；仓库／设计源文件保留原项目位置。本轮为仓库工作流修订，不触发部署模板安装，也不自动提交推送或修改已交设计。

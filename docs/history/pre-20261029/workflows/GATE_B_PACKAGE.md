# Gate B 方案包｜定义、清单与收敛规则

- 状态：active
- 更新：2026-10-20
- 适用：Scheme → Gate B → 正式 Drawing
- 关联：[`PIPELINE_WORKFLOW.md`](../../../../workflows/PIPELINE_WORKFLOW.md)、[`SCHEME_DRAWING_REVIEW.md`](../../../../workflows/SCHEME_DRAWING_REVIEW.md)、[`../templates/PROJECT_TEMPLATE.md`](../../../../templates/PROJECT_TEMPLATE.md)

## 1. Gate B 是什么

Gate B 不是“所有问题都解决了”，而是：

> 用户批准**一个具体版本**，认为它具备进入正式 Drawing 的技术准备度，并接受已列明的 known-unknown。

因此 Gate B 需要三样东西同时存在：

1. **可审的方案包**：总图、平面、剖面、面积、功能、流线、结构逻辑、规范风险、交接资料。
2. **可追溯的版本**：模型、图册、面积表、决策记录绑定同一个版本号。
3. **明确的 known-unknown**：不是“以后再说”，而是写清 owner、影响、下一步和用户是否接受。

没有第 3 项，Gate B 会退化成无限深化；没有第 1–2 项，Gate B 会退化成“用户说继续”。

## 2. Gate B 通过条件

以下五项必须同时满足：

| 条件 | 判定 |
|---|---|
| 用户明确批准 | `DECISIONS.md` 有 Gate B 记录，写明版本、原话、冻结范围、可调整项 |
| 方案包完整 | 12 项清单中没有 `blocking`；`known-unknown` 已列明并被用户接受 |
| 版本唯一 | 模型、图册、面积表、决策记录指向同一版本；旧版保留但不冒充当前 |
| 技术准备度 | 结构、消防/疏散、机电空间、B1 容量达到“可进入 Drawing 深化”的程度，而不是“已施工图” |
| 交接可用 | Drawing 能按 `ARTIFACTS.md` manifest 直接接收，不需要猜上游 |

“技术准备度”不等于“全部计算完成”。允许 known-unknown 的例子：幕墙节点未定、精装未定、设备型号未定；不允许 blocking 的例子：法定 GFA 未核、主要功能面积缺口未解释、B1 车位/藏书容量未闭合、消防楼梯数量/宽度明显不足。

## 3. 12 项 Gate B 清单

每项只能标一个状态：

- `closed`：有证据，当前版本可核查。
- `known-unknown`：已知缺口，写明 owner、影响、下一步、用户是否接受。
- `blocking`：不解决就不能提交 Gate B。
- `not-applicable`：本项目确实不需要，写明理由。

| # | 项目 | 最低证据 | 常见 blocking |
|---|---|---|---|
| 1 | 场地与红线 | 总平、真北、法定红线/研究边界、道路与湖岸高程、退界、7 段道路线处理 | 体量与道路投影相交未处理；把研究多边形当红线 |
| 2 | 体量与围护 | 主体/玻璃尺寸、角度、层高、标高、屋面、幕墙范围 | 尺寸与批准版本不一致；层高/标高未统一 |
| 3 | 各层平面 | 1F–5F + B1，同比例，房间名/编号、门窗、核心筒、楼梯、电梯 | 缺层；房间边界不闭合；门窗宿主不明 |
| 4 | 关键剖面 | 至少 2 张：报告厅/湖侧；核心筒/竖向交通 | 剖面与平面对不上；标高错误 |
| 5 | 面积台账 | 地上/地下、各层、计取/扣减、条件性情景、法定 GFA 口径 | 面积口径混用；把物理楼板当 GFA；缺口未解释 |
| 6 | 功能闭合 | 任务书 vs 实际，逐项差额、用户批准的缩减、未闭合项 | 大额功能缺口用“小幅调整”掩盖 |
| 7 | 流线 | 公共/办公/后勤/书刊/车行/无障碍/夜间/疏散，宽度与竖向 | 只画箭头没有门宽/净宽；后勤穿越公共 |
| 8 | 结构 | 柱网、跨度、转换、长跨、B1 传力、屋面梁位 | 柱网只是空间候选却写成已设计；B1 柱不落地 |
| 9 | 消防/疏散 | 楼梯数量/宽度、门、前室、分区、距离、人数、防烟排烟 | 只做探针碰撞，没有疏散合规判断 |
| 10 | 机电空间 | 总机房、空调机房、配电、给排水、管井、设备运输、噪声振动 | 机房在报告厅下未处理；设备无运输路径 |
| 11 | B1 容量 | 车位（含 10%/90%）、坡道、书库/书架、荷载、覆土、防水 | 车位数≠合格泊位；书架容量无产品/承载依据 |
| 12 | 版本与 manifest | 模型/图册 hash、页码、图号、对象状态标签、测试对象隔离 | PDF 混合两代页码；测试对象混入交付模型 |

## 4. 包的结构

建议项目内建立：

```text
GATE_B/
  GATE_B_MEMO.md          # 一页结论 + 12 项表 + known-unknown
  AREA_LEDGER.csv         # 面积台账（含口径与来源）
  PROGRAM_LEDGER.csv      # 功能闭合（任务书 vs 实际）
  ARTIFACT_MANIFEST.csv   # 文件、版本、hash、页码、状态
  PLANS/                  # 总平、各层平面、剖面（PDF/PNG）
  RISKS.md                # 风险与回退
```

不要求新建一套模型；`GATE_B/` 只放**当前版本**的导出和台账，历史版本留在原 Stage 目录。

## 5. 收敛规则（防止无限 Bxx）

1. **一次只开一个 blocking 主题。** 新开 Bxx 前，先在 12 项表里指出它解决哪个 `blocking`；否则不做。
2. **时间盒 3 个工作日。** 到期时：能 closed 的 closed；不能的写成 `known-unknown` 或 `blocking`；`blocking` 仍多则提交“条件 Gate B”，由用户决定是否接受。
3. **不用渲染/排版补方案缺口。** 效果图不能替代平面、剖面、面积和规范风险。
4. **不改已冻结范围。** 用户已批准的体量、面积、停车比例，修改必须新建决策 ID，不能静默改。
5. **每次修改只影响必要文件。** 改一层平面就同步该层面积、剖面、门窗表和 manifest；不做全库重生成。
6. **旧结论标失效。** 旋转、B1 重排、功能调整后，旧车位/书库/疏散结论标 `OUTDATED`，不得继续引用。

```markdown
- 图册：`xxx.pdf` / 页数 / hash

- 结论：PASS / CONDITIONAL PASS / FAIL
- 用户决策：`DECISIONS.md` D-xxx

## 12 项状态

|---|---|---|---|---|

## Known unknowns
| ID | 缺口 | owner | 影响 | 下一步 | 用户是否接受 |
|---|---|---|---|---|---|

| 文件 | 版本 | hash | 页码/图号 | 状态 |
|---|---|---|---|---|

## 回退条件
- 若 ... 则回到 Scheme / Gate B。
```

## 7. 反模式

- 把“继续”“可以”“先做图”当成 Gate B 批准。
- 用“再研究一版”代替 blocking 判断，B27、B28 无限增加。
- 只做碰撞/探针，不做规范与容量判断。
- 面积表与模型不同步，或只用一张总表不写口径。
- 图册页码/版本混用，下游不知道哪页是当前。
- 测试车位、书架原型、DirectShape 楼梯留在交付模型里。
- 把 known-unknown 藏进正文，不在 memo 里单列。

## 8. 与现有流程的关系

- Scheme 在 Gate B 前可用 CAD/Revit 验证，但按 [`SCHEME_DRAWING_REVIEW.md`](../../../../workflows/SCHEME_DRAWING_REVIEW.md) 标候选、可回滚、有回读。
- Gate B 通过后，Drawing 只接收 `GATE_B/` 的当前 manifest，不从聊天记录猜设计。
- 任何影响总图、平面、剖面、面积、结构、消防的修改，回到 Scheme 并重新过 Gate B；只影响表达/细节的修改在 Drawing 内处理。
- Gate B 不是 Gate C；Drawing 仍需 Gate C 的人工图纸检查。
- Gate B 提交前，六个功能包与所有当前层绘图包必须在 `REVIEW_MATRIX.csv` 有审查记录；未审的包不算完成。

# 方案设计与画图的共同检查约定

适用范围：Gate A 之后的方案深化、CAD/Revit 验证、Scheme→Drawing 交接，以及 Gate C 前的建模出图。沿用现有六角色及四个人工 Gate；不改变可视化、渲染、相机和汇报流程。

## 1. 阶段由任务与批准状态决定

- **方案验证**由 Scheme 负责：允许在任务授权内使用 CAD、Revit、简化模型与计算工具测试尚未冻结的方案；记录研究目的、范围、候选状态和恢复方式。已有正式模型须有可恢复检查点，实验用事务回滚、设计选项或工作副本隔离。用户指定持续修改同一文件时，在该文件中维护唯一当前方案，恢复点另行保存。
- **正式生产**由 Drawing 负责：只有完整交接包与用户对具体版本的 Gate B 批准同时具备，才开始正式 BIM 和成套制图。研究模型不自动升级成冻结模型；沿用时逐项检查并转换所需对象。
- Gate A 选择概念，Gate B 批准完整方案，Gate C 检查模型图纸。内部技术检查不新增人工审批。用户说“继续”、喜欢某张图或允许使用 Revit，均不自动扩大为 Gate B 批准。
- 在已授权范围内自主处理普通命名、整理、常规修复与验证；集中提交重大设计选择。某项待定时继续不受影响的工作，保留待决项，不用假定批准推进依赖工作。用户要求停止时停止执行。

## 2. 设计意图与审美基准

在现有 `DESIGN_THESIS.md` 维护意图卡，决定写入 `DECISIONS.md`，证据位置写入 `ARTIFACTS.md`；不另起平行事实源。

| 字段 | 要求 |
|---|---|
| 意图 ID / 版本 / 来源 | 用户原话、带标注草图、明确批准的图面及其决策 ID；区分原话与 AI 解释 |
| 建筑目标与理由 | 核心概念、比例与层级、方向与穿插、虚实轻重、空间序列、人的尺度、立面与构造秩序 |
| 不变量 / 可调范围 | 哪些决定方案身份，哪些能自主深化，哪些变化需要用户重新确认 |
| 偏离迹象 | 例如主要公共路径被后勤截断、平面尺度接近但视觉上退化成外挂附楼；不是固定的风格偏好 |
| 验证证据 | 对应平面、关键剖面、固定轴测及必要的人视点，注明比例、镜头、模型版本 |
| 当前判断与处理 | 保持 / 削弱 / 违背 / 无法判断；写原因、位置、责任和下一动作 |

意图基准随用户明确的新决定更新，旧基准保留并标记被替代。不要永远强套最初图形，也不要用后来的 AI 解释改写用户原意。概念图的笔迹颜色不构成立面材料批准。

### 视觉对照

在体量、总平、核心筒、重要通高空间、结构或主要立面变化后，以及典型做法复制和重要提交前，进行同版本视觉复核；普通不影响建筑关系的小修改按影响范围抽查。

- 固定同尺度总平和能暴露主次关系的多向白模轴测；体量研究通常保留四向。
- 固定穿过核心空间与竖向交通的剖面；按项目选择主要到达、公共空间、景观侧等人视点。
- 将批准基准与当前结果并排，保持可比较的镜头、裁切、比例和显示规则，标出变化。
- 同时观察平面比例与三维观感：高度、遮挡、外露长度、落地方式和透明度都会改变视觉地位。尺寸或重叠率是证据，不能单独证明审美成立。
- 白模判断体量和空间，材质显示判断虚实与表面关系；禁止用特殊机位、裁切、遮挡、颜色或装饰隐藏真实偏离。不得给出无证据的自动审美总分。

这里的固定人视点用于方案与模型核对，不替代后续 Gate D 的正式表现机位选择。

### 偏离协调

| 来源 | 动作与责任 |
|---|---|
| 图面无法读清 | Drawing 修复线型、文字、可见性和裁切，再看原几何；不能靠表达掩盖设计问题 |
| 建模偏离已确认方案 | Drawing 修复尺寸、方向、标高、类别或宿主，重导受影响图纸 |
| 深化破坏意图 | Scheme 成组协调功能、结构与空间，先比较保持核心意图的调整 |
| 真实条件与原意图冲突 | Scheme 提供原意图、当前偏离、原因、保持意图的备选和必要的偏离方案，附平剖体量及技术代价，由用户决定 |

Director 记录版本、批准范围和责任，不替用户决定审美，也不增加独立审批角色。用户批准的调整同步到意图卡、模型、图纸和检查记录。

## 3. 方案深化的内部检查顺序

S1—S5 是可循环的工作层级，不是新的 Gate，也不要求每层都停下来问用户。按依赖推进，每轮选一个可验收工作包；重大选择按用户授权审核。

| 工作层级 | 主要证据与退出条件 |
|---|---|
| S1 场地与体量 | 校准底图、单位、坐标、方向、范围；比较必要的少量备选，测交集/并集/占地与楼面容量，检查主次层级及到达体验 |
| S2 功能与平面 | 全层功能、面积口径、使用容量、出入口、服务核与运营边界能核对；先建立合理轴网/柱网原则再大量细分重复构件 |
| S3 剖面与技术协调 | 平剖同步验证净高、结构支承、楼梯电梯、洞口、中庭、通高与屋面；功能和构造支持核心空间体验 |
| S4 综合复核 | 当前实际图纸与模型上的容量、交通、运营、无障碍及规范风险检查；受变更影响的旧结论重新验证 |
| S5 技术交接 | 图纸、模型、面积、意图基准、决策、风险和表达深度一致，具备技术准备度后提交用户 Gate B |

场地研究范围、校园范围线、法定用地红线、建设退界须分别注明来源与可靠性。图面上下左右不得默认替换成地理方位。相对角度需记录有向轴或标角方式，绝对朝向另记；整体旋转不保持道路、景观和入口关系。

## 4. 唯一数据口径与表达深度

事实、要求、解释、候选、假设与失效资料分开。项目阈值、建筑类型、语言、比例和容量要求从 `BRIEF.md` / `DECISIONS.md` 读取，不能把某项目尺寸、角度、停车比例或软件地址写成通用默认值。

### 面积与容量

- 分列投影/占地、实体楼板、Room 边界、净使用、功能分配和适用规则下的建筑面积；写明构造、井道、楼梯、通高、架空、平台与屋面的处理方式。
- 重叠区只计一次，共享布置不重复计数；综合测算房间中的交通和服务另分用途，不能全记成主要功能。任务书未明确的“面积”口径必须解释。
- 每层功能分配与实际几何闭合，单列未分配区、差额及原因；总面积合适不能抵消功能缺失。原生 Room 为正不能证明功能或净面积完成。
- 座位、藏书、停车等先分清对象和计数边界，再用真实尺寸的布置检查墙柱、门叶、洞口、操作与通行空间。容量系数附来源和利用率；只画矩形、做单次转弯或统计示意数量，不能宣布完整容量通过。
- 需要独立运营时，逐种状态画出开放区、受控门、卫生服务、水平路径及连续竖向到达/疏散；受保护疏散与日常开放楼梯分别判断。

### 表达状态

| 状态 | 可以支持的结论与限制 |
|---|---|
| 体量 / 功能色块 | 形态、分区和初步几何；不证明构造和使用成立 |
| 二维布置 | 平面候选容量；不等于三维实例或全部净空检查 |
| 三维占位 | 明确范围的包络检查；不等于正式类别、产品或系统 |
| 原生 BIM / 可靠族 | 可进一步核查类别、约束、宿主、切洞、参数与跨视图数据；仍需建筑验证 |

同一成果可含不同深度，按对象登记而非整栋贴“完成”标签。测算分隔线可用于明确标注的面积研究，不能冒充墙、围护或防火分隔。

## 5. 成组变更与检查失效

在现有 `ARTIFACTS.md` 记录：变更 ID、原因、前后版本、保持/重新打开的意图、受影响对象/楼层/视图/台账、失效检查、责任与复查证据。按工作包记录，不要求每个鼠标动作创建 Issue。

| 变更 | 至少检查 |
|---|---|
| 旋转 / 平移 / 尺寸 / 层数 | 红线、道路、地形、景观朝向、入口、地下室、坡道、面积和视觉层级；列明哪些对象未变换 |
| 核心筒 / 货梯 | 全层井道、候梯、楼板洞口、梁柱、门与门叶、家具书架、运输及地下联系 |
| 中庭 / 通高 / 架空 / 屋面 | 上下层支承、边界、采光、净高、到达、面积、结构与运营 |
| 家具 / 书架 / 停车 | 有效容量、工作空间、通道、门叶与完整使用路线 |
| 模板 / 裁切 / 比例 / 标注 | 几何与数据有无被隐藏、文字与轴号、跨图对应和实际导出 |

状态从“有效”改为“待复查”，经新证据恢复；上游变化后不能沿用旧版零碰撞或容量结论。先诊断根因、比较成组调整，再改模型，避免不断局部挤让。

## 6. 画图与模型操作检查

- 工具前检与写入权限分别验证。查询实际文档/路径、单位、标高、视图及模型状态；按当前本机或远程环境选择链路，不照搬历史地址。只读、回滚写入、构件与导出能力分别登记。
- 重要写入先有恢复点和小样。事务提交/重生成后读取需要更新的面积与边界；试算同样安装失败处理，检查回滚状态，不让警告模态窗口无限阻塞后续调用。
- 超时先检查模态、连接和未完成事务，不重复排队写模型。自动恢复有限重试仍失败时请求明确的人工解除动作；恢复后核对测试构件残留、房间、警告和保存状态，再续作。
- 墙柱、楼梯和跨层构件按实际竖向范围/实体检查，不能仅按所属标高筛选；明确采用的采样高度和精度限制。局部探针无碰撞不等于完整通道、净宽或疏散通过。
- 更新视图前识别尺寸、标签、二维家具、模型对象和其他依赖；不要清空整类注释后遗失布局。优先关联 Tag / Schedule，手写或二维例外注明来源和同步责任。
- 一个活动模型保持单一写入入口；独立分析可按授权并行，写入和状态更新串行。
- 当前模型和图册沿用稳定入口；内部恢复点保留历史，发布页标明版本与状态。不要把每轮小修都交付成一组新文件；用户指定命名语言优先，没有要求时不臆造项目偏好。

## 7. 每个重要工作包的共同验收

| 检查线 | 必须回答 |
|---|---|
| 设计意图与审美 | 比例、主次、虚实、空间体验是否保持？固定对照图中哪里削弱，怎样协调？ |
| 空间与功能 | 各层面积、容量、运营和连续路线成立吗？哪些仍只是候选？ |
| 模型与技术 | 几何、标高、支承、孔洞、对象语义、宿主及相关规范前提正确吗？ |
| 表达与交付 | 当前模型、图纸、表格与决策同版吗？实际导出是否清楚且没有掩盖问题？ |

每条结论带版本、对象/范围、方法、结果、限制与证据位置。软件无警告只是软件状态，不能替代其他检查线。先导出能显示本次变化的平面、关键剖面和三维并实际观看；影响多层或多个空间时补足相关视图，不检查无关全部历史图。

Gate B 状态分为“深化中”“技术资料可审核、待用户批准”“已通过”“变更后待重新审核”。未解决的关键场地、主要功能/容量、空间意图或技术矛盾不能被普通遗留细节掩盖。Drawing 不得默补；Gate C 的正式标准和后续阶段入口保持原有要求。

### 7.1 绘图增量审查

一个绘图包 = 同一层、同一空间组或同一变更组；至少包含平面、关键剖面、必要的三维/人视点、面积/容量更新。

每完成一个绘图包，Drawing 不自判完成，先由 Scheme 复核：

- 方案完成度：功能、面积、流线、结构逻辑是否达到本包目标；
- 设计美感：比例、主次、虚实、空间序列、人的尺度是否保持意图卡。

结论三选一：`PASS` 进入下一包；`REVISE` 由 Drawing 修改，最多 2 轮；`RETURN_TO_SCHEME` 说明方案问题，回到 Scheme，必要时由用户决定。

记录包 ID、版本、四条线结论、证据、限制与下一包；写入现有 `ARTIFACTS.md` 变更表或 `REVIEW_MATRIX.csv`，不新建平行台账。不新增人工 Gate；用户只在重大审美或方案选择时介入。触发条件是完成一个绘图包、重大变更、复制典型做法前；不要求每张图都停。

### 7.2 功能包审查（跨楼层）

按功能系统而不是单层组织。默认六个功能包：公共/阅览、书刊/后勤、办公/行政、车行/停车、夜间/独立运营、无障碍/疏散。项目可按实际调整，但必须覆盖全部主要使用与运营状态。

每个功能包至少回答：

- 功能面积/容量是否闭合，差额在哪里；
- 起点—路径—终点是否连续，跨层竖向节点（楼梯、电梯、货梯、坡道）是否唯一、可读；
- 门宽、净宽、净高、转折是否够；
- 运营边界（门禁、夜间分离、后勤不穿公共）是否成立；
- 与结构、消防、机电有没有明显冲突；
- 证据：路径平面、关键剖面、节点放大、面积/容量表。

结论同样三选一，记录到 `REVIEW_MATRIX.csv`，`kind=function`。功能包审查主要覆盖 Gate B 第 6 项功能、第 7 项流线、第 9 项消防/疏散；绘图包审查主要覆盖第 3/4/12 项。两者交叉时，先由功能包定骨架，再由绘图包细化；功能包受影响后必须复查。

## 8. 交接与参考材料

建筑 Case RAG 用于空间、场地、审美和组织方法；Revit 工程/竞赛与 Autodesk 参考用于对象、建模、样板和出图方法。沿用现有检索证据卡，补齐“项目问题→来源与适用条件→采用方法→落图位置→本项目验证→采用/拒绝理由”。无命中如实记录；获奖或官方身份不能替代项目验证。规范原文适用判断与可复核的数值计算分别记录。

# 一个主控，按任务使用专业能力

2026-10-29实战修订。替代固定六Agent、四个人工Gate和强制Issue交接架构。旧资料保存在[历史目录](history/pre-20261029/README.md)，不能继续作为本轮执行限制。

## 默认运行

当前Agent同时承担设计、研究、建模、制图、检查和表达责任，连续完成用户授权的工作。`agents/`是能力说明，不要求用户分派六个人或重复解释设计；不按模型名称固定高低级身份，不为普通修改更换聊天。

用户控制设计方向和交付要求；明确委托Agent判断、持续优化或无人值守执行时，Agent在授权范围内自行决策、看图、修正并接续。普通命名、排家具、选工具、修复导出、调字和机位不逐项请求确认。改变明确冻结的重要决定或需要新的外部授权时，再集中提出具体可见的取舍。

## 能力与入口

这些能力可以在一个任务内连续切换。只读当前问题有关的skill和参考，不把整个库一次塞入上下文。

## 状态与接续

小项目默认只维护 `PROJECT.md`、`BRIEF.md`、`DELIVERY.json`，反馈在PROJECT内列短表即可；已有项目保留原文件，不强迫重建目录或迁移台账。复杂项目才拆出FEEDBACK、DESIGN_THESIS等文件。

每个设计范围写明当前依据：建筑尺度／功能、场地、立面表现、正式图纸分别引用哪份文件或修订。主控负责同步，不把每个软件都称为唯一事实源。断点只需：做完什么、当前文件、仍存在什么问题、下一步在哪里。

## 内部检查代替重复审批

概念可编辑、尺度可核对、工程图可读、图件同版、PDF可打印，是内部完成条件。它们不是新增人工Gate。历史Gate仍可作为当时决策证据，但不阻止概念阶段用Blender，不要求用户再次批准已经授权的动作。

软件返回success、零警告、文件非空或数量相等，只能证明对应技术事实，不能代替看图与设计判断。主控自己读取实际模型、截图和整张PDF来检查，不能把未完成的自检交给用户。

## 实际需要协作时

仅在用户或适用指令明确要求并行Agent时分工；否则不自动创建子Agent。对同一Revit文档、SketchUp模型或Blender场景只保留一个写入者。独立检索和离线图像工作可按可用工具并行，结果仍由主控整合。

技术故障先推进不受影响的工作。超时不重放写入，不擅自强杀用户软件；保存最小断点。详细主线见[制作流程](../workflows/PIPELINE_WORKFLOW.md)。

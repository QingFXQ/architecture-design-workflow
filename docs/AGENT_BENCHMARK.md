# 建筑设计 Agent Benchmark 协议

方案与画图按[共同检查约定](../workflows/SCHEME_DRAWING_REVIEW.md)区分研究与正式生产；补充[行为验收情景](../benchmarks/scheme-workflow/scheme-drawing-review.md)检查意图审美与技术协调。模拟 Gate 或静态分数不授权写入真实模型。

## 1. 目的与适用范围
本协议用于评估 `Concept Design Agent` 与 `Scheme Design Agent`。
评估对象是 Agent 在真实建筑课程设计情境中的工作质量。
评估对象不是文案、图像风格、模型调用成功率或单次演示效果。
本协议同时检验设计判断、阶段边界、交接质量和可修正性。
适用的工作流为：任务书 → Concept → Gate A → Scheme → Gate B。
Gate A 与 Gate B 的用户决策权不可由 benchmark 评分者、Director 或 Agent 代替。
本协议不替代专业规范审查、建筑师执业判断或课程教师评图。

### 1.1 Benchmark 目标
建立一组接近真实课程任务书的、可重复运行的建筑设计测试。
使 Concept Agent 的输出能够被检验为真实问题、建筑操作和可选方向。
使 Scheme Agent 的输出能够被检验为概念继承、空间落实和 Revit 前准备。
使失败不止得到低分，而是能定位到 Agent 指令或 Skill 的具体规则。
使修正规则可被同一题目再次验证，而不是只靠主观说明“已改进”。

### 1.2 设计原则
**真实。** 题目采用课程任务书常见的项目类型、基地条件、面积表、开放关系和冲突。
**同题同证据。** 同一轮的 Agent 必须接收同一份输入包、同一版本和同一可用资料。
**可重复。** 每题有固定必填字段、明确变体字段、固定评分表和可复现运行步骤。
**可评分。** 每项维度使用 0—5 分，并以输出中的可核查证据评分。
**不纵容幻觉。** 未知项必须标注为未知、假设或待确认；编造事实不得以“设计想象”抵消。
**守 Gate。** 概念未通过 Gate A 不进入方案；方案未通过 Gate B 不进入正式 Drawing，允许已授权且可恢复的 Scheme 验证。
**同等比较。** Concept 的每个方向采用同一 11 项结构；Scheme 的各变体采用同一确认包结构。
**失败可回馈。** 失败案例必须形成根因、修正规则、回归题目和复测结论的闭环。

### 1.3 非目标
不以效果图精美程度判断概念是否成立。
不要求 Agent 在 benchmark 中直接建立 Revit 模型。
不把 `building-code-check` 的输出当作执业合规结论。
不允许为了便于评分而删除真实项目中的矛盾、未知项或用户选择。
不允许用更换题目、减少方向数或降低交付物来掩盖失败。

## 2. 运行单位与版本规则
一次 benchmark 的正式单位是一张 Multica issue。
一张 issue 只指定一个主责 Agent：Concept 或 Scheme。
每张 issue 必须写明项目版本、任务轮次、输入文件、允许读取范围和验收标准。
输入包必须以只读方式归档；评分时不得用运行后新增的事实反向补强输出。
输出包必须保留原文、图表或图像引用、工具调用记录和最终评分表。
每次运行使用唯一主题名，例如 `university-museum-slope-loop-v1`。
同题复测增加版本后缀，例如 `university-museum-slope-loop-v2`。
评分者在阅读输出前先阅读题目与评分规则，但不得替 Agent 补写缺失内容。
若运行环境缺少所需工具或资料，必须记录为环境失败，不得记为设计通过。
若 Agent 明确且正确地阻塞在关键缺失输入上，可在“契约执行”得分中获得相应证据分。

## 3. 测试题目库设计
每个题目由“固定字段 + 可换字段”组成。
固定字段保证同类项目可横向比较。
可换字段用于构造难度、避免记忆性作答，并测试策略在不同条件下是否仍有因果链。
所有题目均应提供项目名称、课程阶段、任务书、场地资料、面积表、用户偏好、已知决策和交付要求。
场地未知时必须明确写为未知，不得以模糊示意图逼迫 Agent 虚构事实。

### 3.1 模板 A：高校博物馆
**任务书要点**

- 为高校校园设计一座兼具校史、学科特色与公共教育功能的博物馆。
- 项目须同时服务校内日常使用、校友活动、临时展览和对公众预约开放。
- 设计应把校园公共性、展览秩序、藏品安全和报告活动之间的冲突转为建筑组织。
- 需回应校园步行系统与特定场地高差，不得把博物馆仅处理为孤立展厅盒子。
**场地条件**

- 基地位于校园主步行轴与教学区交界，南侧为主要到达道路，北侧面向安静绿地。
- 基地约 120 m × 90 m，南高北低，整体高差 4 m。
- 东侧有学生高频步行流线，西侧临近后勤道路；西南侧为消防可达边。
- 夏季西晒、南侧人流噪声和北侧绿地视线均为已知环境条件。
**功能面积**

- 建筑面积控制为约 8,000 ㎡，允许偏差 ±5%。
- 常设展 2,000 ㎡，临展 1,000 ㎡，大厅与集散 650 ㎡，报告厅 450 ㎡。
- 教育活动与公共服务 700 ㎡，办公 450 ㎡，藏品库与修复 900 ㎡。
- 后勤设备 750 ㎡，交通及必要服务面积由 Agent 合理配置并说明。
**约束**

- 公众入口、团体入口与藏品后勤到达必须可区分。
- 常设展、临展和报告厅应能在不同开放时段独立或联动运营。
- 藏品库不得成为公众流线的穿越空间。
- 必须检验高差是否能形成有意义的参观序列，而非仅用台阶造型。
**可换字段**

- 高差方向可改为东高西低；主入口可改至东侧；常设展主题可改为科技史。
- 面积可在 6,500—10,000 ㎡调整；报告厅可改为 300 或 600 座。
- 可增加“入口弱、参观流线平”的教师反馈作为第二轮修订输入。

### 3.2 模板 B：幼儿园
**任务书要点**

- 为 12 班幼儿园设计安全、可识别且支持游戏学习的日常环境。
- 项目要平衡儿童独立探索、教师可看护、家长接送与后勤管理。
- 课程要求关注室内外连续性、班级单元与共享活动空间的关系。
**场地条件**

- 基地约 85 m × 70 m，位于住宅区边缘，东侧为城市支路，南侧邻近已有住宅。
- 北侧有成片保留乔木，西侧受午后交通噪声影响，场地总体平坦。
- 家长接送只能从东侧进入，后勤车辆须从西北角短时到达。
- 南侧日照资源较好，但需控制对住宅的视线与噪声影响。
**功能面积**

- 建筑面积控制为 4,200 ㎡，允许偏差 ±5%。
- 12 个班级活动单元各 150 ㎡，共享多功能厅 350 ㎡。
- 厨房与配餐 220 ㎡，保健与行政 260 ㎡，教研 180 ㎡。
- 门厅、接送缓冲、设备、储藏、交通和卫生间由 Agent 配置并说明面积逻辑。
**约束**

- 每个班级应有可直接使用的室外活动联系，且不得以穿越车行区实现。
- 儿童、家长、教职工、后勤和疏散流线必须分别说明交汇与分离。
- 建筑不宜超过三层；垂直交通和无障碍连续性必须可检查。
- 不得以“童趣”“森林感”等词替代可验证的空间与看护策略。
**可换字段**

- 班级数可改为 9、15 或 18 班；可设置 1.5 m 微地形或现有树木保留线。
- 东侧道路等级、周边住宅高度和噪声来源可改变。
- 课程偏好可改为蒙特梭利、混龄或社区共享，但须作为偏好而非事实。

### 3.3 模板 C：社区中心
**任务书要点**

- 在混合居住社区中提供多年龄共享、日间办事、夜间活动和应急联络空间。
- 项目须处理开放公共性与可分时管理的矛盾。
- 课程要求建筑成为街道与社区花园之间可被日常使用的门槛，而非封闭会所。
**场地条件**

- 基地约 100 m × 55 m，南侧临城市支路，北侧连接现有社区花园。
- 东端邻近菜市场和公交站，西端临较安静的住宅入口。
- 场地平坦，但东南角为高峰人流与噪声点；消防车从南侧进入。
- 现有南北向慢行路径经过基地，应判断保留、转折或吸收的方式。
**功能面积**

- 建筑面积控制为 3,600 ㎡，允许偏差 ±8%。
- 社区大厅与信息服务 300 ㎡，多功能活动厅 500 ㎡，老年活动 350 ㎡。
- 青少年学习与创作 280 ㎡，社区卫生与咨询 220 ㎡，可共享教室 360 ㎡。
- 管理、储藏、设备、卫生间、交通和室外半开放空间由 Agent 配置并说明。
**约束**

- 晚间活动厅应可独立开放，且不穿越日间行政区。
- 老年、儿童与服务配送流线须避免未经处理的冲突。
- 面向花园的一侧应产生可使用的室内外界面，不得只设景观玻璃墙。
- 需说明社区路径被建筑改变后的公共性收益与管理代价。
**可换字段**

- 可改为存量厂房改造与扩建；可加入雨洪花园或 2 m 高差。
- 功能可增加共享厨房、托育点、数字服务站或小型体育房。
- 可将夜间运营限制改为“仅活动厅和卫生间开放”。

### 3.4 模板 D：公共图书馆
**任务书要点**

- 为城区新开发片区设计兼具阅读、学习、儿童服务和社区交流功能的公共图书馆。
- 项目应回答安静阅读、活跃交流、儿童活动和图书后勤的并置关系。
- 建筑需提供清晰进入方式和可持续的自然采光策略。
**场地条件**

- 基地约 110 m × 80 m，北临城市公园，南临公交集散广场。
- 东侧为六车道城市道路，西侧为中学；基地东北角有可借景水面。
- 场地南低北高，高差约 2.5 m；夏季西南日晒明显。
- 公众步行高峰来自南侧，儿童和学生高频到达来自西侧。
**功能面积**

- 建筑面积控制为 6,000 ㎡，允许偏差 ±5%。
- 成人阅览与开架 1,500 ㎡，少儿阅览与活动 850 ㎡，自习与数字学习 700 ㎡。
- 报告与展览复合空间 500 ㎡，咖啡与公共服务 250 ㎡。
- 图书加工库房 450 ㎡，行政 300 ㎡，交通、设备与服务面积按运营逻辑配置。
**约束**

- 少儿活动可被独立管理，但不应被完全孤立。
- 安静阅读区应与高噪活动区形成可解释的距离、标高或界面关系。
- 图书后勤接收、加工、上架和读者流线必须分别描述。
- 采光判断必须能回到平面、剖面和体量，不能只以“通透”形容。
**可换字段**

- 总面积可改为 4,500 或 8,000 ㎡；可加入 24 小时自习入口。
- 水面可替换为地铁出入口或历史建筑视线；高差可改为平地。
- 可将部分阅览空间改为社区档案与地方史阅览。

### 3.5 模板 E：小型美术馆
**任务书要点**

- 为当代艺术机构设计小型美术馆，支持灵活展览、教育活动、作品装卸和有限艺术家驻留。
- 设计需将艺术展示的可变性、自然光控制、街区开放性和作品安全转为明确空间关系。
- 课程要求关注小尺度项目如何通过总图、剖面与室内外门槛形成完整体验。
**场地条件**

- 基地约 60 m × 75 m，位于旧街区边缘；南侧是窄街，北侧面向河岸步道。
- 西侧保留一栋两层旧仓库，东侧为新建住宅；基地有 1.8 m 向北下降的高差。
- 货运只能从南侧定时进入，河岸步道是全天公共人流来源。
- 北侧视线和西侧既有建筑是场地机会，东侧住宅私密性是限制。
**功能面积**

- 建筑面积控制为 2,500 ㎡，允许偏差 ±8%。
- 主展厅 650 ㎡，可变展厅 350 ㎡，教育工坊 220 ㎡，多用途讲座空间 180 ㎡。
- 藏品临时库与装卸 250 ㎡，艺术家工作与驻留 180 ㎡，行政 120 ㎡。
- 门厅、商店、卫生间、交通、设备和室外展场按逻辑配置。
**约束**

- 作品装卸不得穿越主要观众聚集空间。
- 主展厅需要明确的高、光和可变分隔逻辑；不得以渲染氛围替代。
- 旧仓库保留、连接或不连接均可，但须说明对展览和公共性的代价。
- 河岸界面应兼顾开放与闭馆后的安全管理。
**可换字段**

- 可改为摄影馆、地方艺术中心或设计展厅；驻留可取消并增设档案室。
- 旧仓库可改为保留树群或工业遗构；高差可调整至 0—3 m。
- 主要展览可设为全人工光、混合采光或以天光为主的不同前提。

## 4. 输入包与受控变量
每次 Concept benchmark 必须提供任务书原文、场地资料、面积与功能、用户偏好、已有决策、当前版本和本轮概念问题。
每次 Scheme benchmark 除上述资料外，必须提供可追溯的 Gate A 决策记录和完整 Concept→Scheme Handoff。
Handoff 至少包括：选中概念、设计问题、核心策略、示例图及用途、用户评价原话、必须保留意图、可调整部分、风险、待验证假设、版本和决策 ID。
评分者须固定同一题目的输入顺序、文件命名和附件集合。
允许改变的字段只限第 3 章各模板明确列出的可换字段。
改动可换字段后，必须生成新主题名、新版本和独立结果记录。
不得在 Agent 开始后口头补充关键信息；任何补充都必须作为 issue 更新并留档。

## 5. 评分制度

### 5.1 评分方法
每个维度使用 0—5 分整数评分。
0 分：缺失、违反明确边界，或以编造事实支撑结论。
1 分：提及了主题，但没有可核查的项目证据或建筑结果。
2 分：存在局部正确判断，但核心关系不完整、相互矛盾或不可执行。
3 分：满足基本要求，有明确证据与操作，但仍有一处重要缺口或风险未闭合。
4 分：证据、操作、图面说明与风险处理完整，能够支撑本阶段人工 Gate 判断。
5 分：在 4 分基础上，清楚揭示关键取舍、可验证方法和失败回路；无关键矛盾或越级推进。
每项评分必须引用输出中的具体章节、图名、表格或缺失事实。
不得给“整体感觉不错”的综合理由。
Concept 总分为 8 个基础维度，满分 40 分。
Scheme 总分为 11 个维度，满分 55 分，含 8 个基础维度与 3 个 Scheme 专项维度。

### 5.2 Concept 与 Scheme 的基础维度

| 编号 | 维度 | 5 分判定要点 |
|---|---|---|
| C1 | 概念回应真实问题 | 项目专属问题包含对象、冲突、证据、边界和可观察成功状态；建筑操作能回应它。 |
| C2 | 避免空洞概念 | 不以风格、情绪或口号充当理由；每一抽象词均转为总图、功能、平面、剖面、流线或空间改变。 |
| C3 | 方向差异与可深化性 | 至少 3 个方向，差异来自组织机制；每个方向都能回答落位、行走、功能、核心空间、体量和室内外关系。Scheme 时改为至少 2 个共享核心概念的可实施变体。 |
| C4 | Gate A 输出完整性 | Concept 的每个方向 11 项逐项可见且不留空；Scheme 仅在验收其输入 Handoff 时检查该项是否完整。 |
| C5 | 概念继承不偷改 | Scheme 对 Gate A 的核心问题、核心操作、用户原话、必须保留项逐项追踪；偏离均有批准记录。Concept 运行中不得预先假定选择。 |
| C6 | 深化深度 / Revit 准备度 | Scheme 的 13 项最低要求全部有图纸或表格证据且均为“已满足”；Concept 应停在概念边界，不越级假装满足。 |
| C7 | 规范风险自查 | 已按适用条件检查防火、疏散、无障碍、日照采光、退界等风险，明确来源、未知项、修改建议与专业复核边界。 |
| C8 | 五段契约执行 | Required Input、Required Output、Exit Criteria、Return Conditions、Next 均与本次状态一致，且下一责任人和 Gate 不越级。 |

### 5.3 Concept 专项评分说明
**C1 概念回应真实问题。**
5 分要求证据链完整：题目与场地事实 → 具体矛盾 → 建筑操作 → 使用与空间结果 → 图面验证。
若替换项目名后问题仍完全成立，C1 不得高于 2 分。
若只改造型或文案即可“解决”，C1 不得高于 1 分。
**C2 避免空洞概念。**
“文化感”“流动”“森林”“开放”等词只有在改变可画空间关系时才可作为辅助描述。
以概念渲染替代场地、功能、流线或剖面推理，C2 不得高于 2 分。
**C3 方向差异与可深化性。**
仅改变材料、色彩、立面图案、名称或渲染气氛的“多方向”按一个方向计算。
不足三个真实方向，除非题目已有经过记录的例外，C3 为 0 分。
**C4 Gate A 输出完整性。**
11 项依次为：核心问题、核心概念、空间策略、功能策略、流线策略、体量策略、场地策略、参考案例、示例图、优点、潜在风险。
任一方向缺少任一项，或将多项混写到无法核查，C4 不得高于 2 分。
没有示例图清单与“参考 / 示意 / 项目草案”身份说明，C4 不得高于 3 分。
**C5—C7 的 Concept 适用方式。**
Concept 必须保持“概念包待选择”状态，未获用户选择不得进行方案深化或宣称可进入正式 Drawing。
Concept 应公开需要 Scheme 验证的面积、结构、规范与剖面风险，而非虚构已经解决。
因此，正确停止与正确交接可得高分；越级细化不得加分。
**C8 五段契约执行。**
Required Input 缺失关键事实时应提出最小补充信息。
Required Output 必须是多方向概念包、示例图清单、比较表和交接建议。
Exit Criteria 必须确认用户明确选择并由 Director 记录 Gate A，才可交给 Scheme。
Return Conditions 必须能把事实冲突、方向不够不同、RAG 误导或无法深化准确退回。
Next 在 Gate A 前只能是用户、Director 或 Concept，不得直接交给 Drawing、Visualization 或 Revit。

### 5.4 Scheme 专项维度

| 编号 | 维度 | 5 分判定要点 |
|---|---|---|
| S1 | 案例 RAG 使用痕迹 | 围绕本轮设计问题检索，记录案例 ID、来源、相似与不同条件、可迁移方法、转译位置、不可照搬内容和证据质量。 |
| S2 | 平面—剖面—体量同步 | 每项关键修改同时回查平面、剖面、体量和流线；矛盾标出位置、根因和同步更新结果。 |
| S3 | 面积合理性 | 完整面积表与任务书核对，主要功能可用，交通、服务、结构占比可解释，偏差有修改或用户确认。 |
**C5 概念继承不偷改。**
没有 Gate A 已选概念、用户原话或核心不变量时，Scheme 不得启动；启动即 C5 为 0 分。
将已选策略改成更易画的体量、流线或表皮而无批准记录，C5 不得高于 1 分。
**C6 深化深度 / Revit 准备度。**
13 项为：总图位置、建筑轮廓、层数、各层主要平面、房间功能、主要尺寸、门窗基本位置、楼梯电梯、层高、关键剖面关系、建筑主要形体、基本结构逻辑、面积基本合理。
每项必须标记“已满足”，并指向相应图纸或表格证据。
任一项为“部分满足”或“不满足”，C6 不得高于 2 分，且状态不得为可进入正式 Drawing。
**C7 规范风险自查。**
必须调用 `building-code-check`；不可用时必须记录不可用、形成初步风险清单并将其作为阻塞项。
将工具成功、模糊地区条文或未复核假设称为“已合规”，C7 为 0 分。
**C8 五段契约执行。**
Required Input 必须包含 Gate A 选择和完整交接。
Required Output 必须包含方案确认包、核心操作矩阵、总图、平面、剖面、流线、体量、面积尺寸、规范自查、风险和 Gate B 比较说明。
Exit Criteria 必须要求概念继承、图纸互核、13 项全满足、完整确认包和用户 Gate B 批准。
Return Conditions 必须能退回 Concept、Director、Scheme 本层或 Gate B，不得把方案缺口交给 Drawing 猜测。
Next 在 Gate B 通过后才是 Drawing Production Agent；未通过时不得进入正式 Drawing。
**S1 案例 RAG 使用痕迹。**
仅列举知名案例名称、图片或“借鉴气质”时，S1 不得高于 1 分。
把案例形式直接复制为本项目方案时，S1 为 0 分。
**S2 平面—剖面—体量同步。**
只提供孤立平面、孤立剖面或孤立体量图，S2 不得高于 2 分。
关键高差、核心空间、交通核、天光、退让和入口必须可在至少两个图面系统中互相验证。
**S3 面积合理性。**
未列出交通、设备、服务或结构相关面积时，S3 不得高于 2 分。
总面积偏差超过题目容许范围且无修改或用户确认，S3 不得高于 1 分。

### 5.5 通过、失败与重跑判定
Concept 通过基线：总分不低于 30/40，且 C1、C3、C4、C8 均不低于 3 分。
Concept 任何一方向少于 3 个真实方向、Gate A 前进入方案深化、擅自替用户选择，均为阻断失败。
Scheme 通过基线：总分不低于 42/55，且 C5、C6、C7、C8、S2、S3 均不低于 3 分。
Scheme 任一 Revit 最低要求非“已满足”、未完成 Gate B 却交给 Drawing、或篡改 Gate A 核心意图，均为阻断失败。
阻断失败必须记录总分，但不得因其他高分掩盖失败。
题目发生实质性输入变化后必须新跑，不得用旧评分覆盖新版本。

## 6. 单次 Benchmark 执行流程

### 6.1 创建与派发
1. 从第 3 章选择一个模板，确定固定字段和允许变体字段。
2. 创建 Multica issue，标题格式为 `Benchmark/<Agent>/<主题>/<版本>`。
3. 在 issue 中附上任务书、场地资料、面积表、用户偏好、决策记录和验收维度。
4. 标注 `benchmark=true`、目标 Agent、输入版本、允许工具和禁止范围。
5. 将 Concept issue 派给 Concept Design Agent；将 Scheme issue 派给 Scheme Design Agent。
6. Scheme issue 必须另外附 Gate A 决策与完整 Concept→Scheme Handoff。

### 6.2 运行控制
1. Agent 只能使用 issue 附件和明确允许的项目事实源。
2. Agent 必须在输出开头说明已读取输入、版本与未知项。
3. 运行期间不由评分者提供口头暗示、案例答案或补充设计方案。
4. 若 Agent 请求关键资料，评分者仅按题目包已有资料回应，并记录请求。
5. 若 Agent 正确阻塞，保留其输出并按 C8 与对应维度评分。
6. 运行结束后立即冻结输出；不允许 Agent 根据评分意见修改原始答卷。

### 6.3 收集与评分
1. 收集 Agent 的最终文本、图表、示例图清单、引用、工具记录和交接内容。
2. 检查是否存在越级推进、未声明假设、虚构事实或直接复制案例形式。
3. 两名评分者独立使用第 5 章评分；每项必须写出证据或缺口。
4. 两名评分相差超过 1 分时，共同复核原始输出后形成一份带理由的最终分。
5. 先判定阻断失败，再计算总分和通过基线。
6. 将结果写入 `docs/benchmark-results/`，文件名采用第 7 章规则。

### 6.4 失败回馈与 Skill 修正
1. 对每个低于 3 分或阻断失败的维度，记录直接失败点。
2. 区分输入缺失、Agent 指令缺失、Skill 规则缺失、工具或检索失败、执行遗漏五类根因。
3. 将根因定位到最小可修改规则，例如“方向差异检查”而非笼统的“概念不够好”。
4. 提出可验证的 Skill 修改：新增检查项、明确禁止项、输出字段或返回条件。
5. 修改对应 Skill 前，保留失败样本和预期改进行为。
6. 用完全相同的输入包重跑；比较所有维度，确认目标维度提升且没有破坏 Gate 或其他关键分项。
7. 把修改前后分数、变更摘要和回归结论追加到原结果文件。
不得把一次失败仅写成“模型能力不足”。
不得把修改结果只描述为“已优化提示词”。
必须说明哪条规则改变了哪种可观察行为。

## 7. 结果记录格式
结果文件位于 `docs/benchmark-results/`。
文件名必须使用真实运行日期、Agent 和主题：
`YYYY-MM-DD-<agent>-<topic>.md`
例如：`2026-08-12-concept-university-museum.md`。

## 8. 首轮执行计划：Museum Demo
首轮使用 [demo/MUSEUM_DEMO_BRIEF.md](../demo/MUSEUM_DEMO_BRIEF.md) 中的高校博物馆任务书。

### 8.1 Concept 首轮
1. 创建 issue：`Benchmark/Concept/university-museum-slope-loop/v1`。
2. 附上 `MUSEUM_DEMO_BRIEF.md`，并把项目固定为 8,000 ㎡、4 m 高差、常设展、临展、大厅、报告厅、办公、后勤与藏品库。
3. 写明本轮概念问题：如何以高差组织既有空间变化的公众参观路线，同时分离藏品后勤与校园日常穿越。
4. 标注南侧为主要到达、东侧学生流、西侧后勤、南高北低；这些为本轮固定场地条件。
5. 明确用户偏好：希望参观路线逐渐下沉；不把该偏好自动等同于已选概念。
6. 要求 Agent 交付 3—5 个明显不同方向，每个方向完整写出 11 项、示例图清单、比较表、风险与待验证项。
7. 禁止 Agent 在 Gate A 前交付完整方案、Revit 指令或擅自选择方向。
8. 冻结输出，按 C1—C8 评分，形成 `2026-08-12-concept-university-museum.md`。
9. 由人工 Gate A 在 Agent 输出中明确选择一个方向，并保留用户原话、选择版本、必须保留意图与可调整部分。
10. Director 将 Gate A 决策写入 `DECISIONS.md`，并形成完整 Concept→Scheme Handoff。

### 8.2 Scheme 首轮
1. 创建 issue：`Benchmark/Scheme/university-museum-slope-loop/v1`。
2. 附上相同 Museum Demo 输入包、Concept 原始输出、Gate A 决策和完整 Handoff。
3. 固定 Gate A 选择为：采用“以高差组织逐渐下沉的参观环线”作为核心策略；禁止删除该策略以换取平面便利。
4. 要求至少两个共享该概念的可实施方案变体，差异可以来自入口、体量、剖面组织或空间序列，不得只改材料与效果图。
5. 要求按设计问题完成 Architecture Case RAG 检索，并留下案例 ID、方法迁移和不可照搬条件。
6. 要求形成核心操作矩阵、总图、各层平面、关键剖面、流线、体量、面积表、主要尺寸、结构逻辑和规范风险报告。
7. 要求完成 13 项 Revit 准备度清单；任何一项不是“已满足”即保持“方案待确认”或“方案阻塞”。
8. 要求调用 `building-code-check`；工具不可用时将其记录为阻塞并提出具体风险清单。
9. 未经人工 Gate B 明确批准，不得把输出交给 Drawing 或宣称可进入正式 Drawing。
10. 冻结输出，按 C1—C8、S1—S3 评分，形成 `2026-08-12-scheme-university-museum.md`。
11. 若通过基线，由人工进行 Gate B；若未通过，按第 6.4 节进入 Skill 修正与同题回归。

## 9. 禁止事项
不得为通过 benchmark 而放宽任何题目约束、Gate 条件、评分锚点或通过基线。
不得在失败后删除原始输出、低分证据、工具不可用记录或评分者分歧。
不得将“写得更长”“图片更多”当作真实问题、可深化性或方案完整性的替代证据。
不得把个人审美、案例名气、渲染质量或模型自信度计入客观设计得分。
不得把用户未明确表达的喜欢、同意或批准解释为 Gate A 或 Gate B 通过。
不得让 Scheme 在 Concept 未选时自行选择概念。
不得让 Drawing、Revit、Visualization 或 Presentation 补救 Concept 或 Scheme 的设计缺口。
不得把 `building-code-check` 的成功状态说成最终合规。
不得用“以后在 Revit 调整”掩盖 13 项准备度中的部分满足或不满足。
不得把案例图像、照片或宣传文字冒充精确平面、剖面、尺寸或结构证据。
不得只记录失败结论；失败必须记录失败点、根因、具体修正建议和同题回归结果。
不得在未完成回归复测前宣称相关 Skill 已修复。

## 10. 协议维护
题目模板、评分锚点和通过基线的修改必须单独记录版本原因。
修改协议时不得回写既有结果；历史结果保留其当时使用的协议版本。
新增题目应先按本协议模板写明任务书、场地、面积、约束和可换字段，再进入题库。
若连续三次同类失败都指向同一 Skill 规则，优先修正规则并用至少一个原失败题和一个变体题回归。
若失败主要由输入包缺失造成，应修正题目输入包，而非惩罚 Agent 或降低评分标准。
本协议以“真实设计判断、阶段边界和可验证修正”优先于单轮分数。

# View Template、Filter 与可见性：让全套图纸一致

## 适用场景

- 适用于一套课程图纸中有多层平面、立面、剖面、三维和明细表视图的项目。
- 目标是将“同类视图必须一致”的规则从人工记忆转为模板控制。
- View Template 保存一组视图属性；模板能应用到多个同类视图。[S1]
- Filter 是按类别与参数条件选中元素后，统一覆盖其显示方式的机制。

## 核心决策

1. 跨多数同类视图都一致的设置，放入 View Template。
2. 同一类别中只有符合条件的元素需突出/隐藏，使用 Filter。
3. 仅一张图的临时例外，使用视图级 Visibility/Graphics 覆盖，并记录原因。
4. 仅一个元素的临时表现，最后才使用 Override by Element。
5. 不以“每张图调到好看”为流程；先定义一类图的表达目标。

## 先建立视图分类

- 建议最少建立：总平、建筑平面、天花、立面、剖面、局部详图、三维表现、协调检查。
- 每类视图明确比例、细节级别、视觉样式、裁剪、范围、标注密度与打印目的。
- 不同用途不要共用一个模板；1:100 总平与 1:50 平面通常应分离。
- 课程作业先控制模板数量在 5—8 个，足以保证一致又不增加维护负担。
- 模板名称包含用途、比例、阶段，例如 `A-PLAN-100-提交`。

## 方法步骤：由一张正确视图反推模板

1. 选择最成熟的一张代表视图，而不是空白新视图。
2. 设置比例、Detail Level、Visual Style、阴影、裁剪与范围。
3. 在 VG 中控制类别、子类别、线型、填充、透明度和导入链接。
4. 添加必要 Filter，再检查标注类别和模型类别的层级。
5. 保存为模板，明确哪些参数受模板控制。
6. 批量赋给同类视图，再只处理合理例外。
7. 打印一张图纸验证线宽和信息密度，不只在屏幕上判断。

## 模板应优先控制的项目

- 视图比例与 Detail Level。
- Model Categories 与 Annotation Categories 的可见性。
- 过滤器及其图形覆盖。
- 视觉样式、阴影、环境光、背景和透明度。
- View Range、Crop Region、Scope Box（视项目需求）。
- Imported Categories、Revit Links 与 Underlay 的显示策略。
- Phase 与 Phase Filter（改造/分期项目尤其重要）。
- Linework 的通用层级不宜靠逐元素覆盖完成。

## Filter：把审图规则变成可重复规则

- Filter 必须有可筛选类别和可比较参数；先确认参数在目标类别上可用。
- 用 Filter 突出“新建墙”“防火门”“待检查房间”“未编号门”比手工上色可靠。
- 一条 Filter 只承担一个审查/表达语义，避免条件过多后无法解释。
- 颜色是辅助，不应是唯一信息载体；配合填充、线型或文字说明。
- 用 `Comments` 等临时参数做课程检查可行，但交付前要清理或转为明确标准字段。
- Filter 覆盖优先在模板中配置，使所有同类图一致。

## 可见性覆盖的优先级

- 项目 Object Styles 是基准，不应为一张图随意改动。
- View Template 是同类图的标准。
- View Filter 是条件化标准。
- 单视图 VG 是明确例外。
- Override by Element 是最后手段，应尽量少且可追踪。
- 家族内的子类别/可见性决定构件如何被项目视图控制；建族时要预留这个层级。[S2]

## 大量图纸的管理方法

- 新建视图后立即套模板，而不是出图前统一补救。
- 复制视图时先判断复制方式：仅模型、带标注、带细节各有不同用途。
- 用 View Template 作为 Project Browser 的组织字段之一，可快速发现未归类视图。
- 为“工作中”“待出图”“已出图”建立浏览器组织或参数，避免选错草稿视图上图纸。
- 一张图纸上的视图命名应可追溯到模板和比例。

## 图形层级建议

- 平面：切到的墙/柱优先强于投影构件；家具和填充次之；注释清晰但不压过模型。
- 剖面：被剖切构件最强，远处投影减弱，背景模型可半透明或隐藏。
- 立面：主体轮廓、开口、幕墙格网和材质图案保持可读，不展示无关内部构件。
- 三维：先保证设计意图和空间关系，不必与施工平面使用同一模板。
- 同一比例的图纸应通过模板维持相近线宽密度；线宽最终要以 PDF/打印判断。[S3]

## 优点

- 一次调好，多个视图同步，显著降低图纸表达漂移。
- Filter 将可核查的模型数据转为可视化 QA。
- 明确覆盖层级能减少“为什么这张图不一样”的排错时间。
- 模板使新建视图可以快速进入可用状态。

## 风险与坑

- 模板锁定参数后，用户以为自己改了视图，实际被模板覆盖；先识别受控参数。[S1]
- 用大量元素级 Override 会让视图无法从模板安全更新。
- Filter 依赖参数质量；空值、拼写不一、实例/类型混用会使结果漏项。
- 从其他项目 Transfer Standards 后，模板可能引用不合适的 Filter、线型或族类别。
- 以屏幕缩放判断线宽会误导；应在目标比例的 PDF 中复核。[S3]

## 不适用情况

- 单一概念透视图不必承受完整工程图模板体系。
- 每张图有完全不同叙事目标时，强行使用同模板会抹掉必要差异。
- Filter 不适合替代模型分类；元素本身类别错了，应先修模型。

## 课程作业建议

- 第一天即创建最少五个模板：总平、平面、立面、剖面、三维。
- 先完成一张“样板平面”和一张“样板剖面”，再复制/套模板。
- 最后两天只允许修模板和少量记录在案的视图例外，避免逐张重调。
- 做一个未编号门/窗的红色 Filter，导出前逐项清零。
- 导出 PDF 后随机抽查三张图：比例、裁剪、隐藏类别、线宽和文字都应符合模板目标。

## 模板发布检查清单

- 核对模板名称是否说明用途与比例。
- 核对每张新视图是否已套正确模板。
- 核对模板控制的比例是否符合图纸。
- 核对模板控制的细节级别是否一致。
- 核对裁剪区域是否留出标注空间。
- 核对 Scope Box 是否应用到对应视图。
- 核对视图范围是否切到正确标高。
- 核对墙、门窗、家具类别的可见性。
- 核对注释类别没有被意外隐藏。
- 核对 Revit Link 的显示策略。
- 核对 CAD 导入线没有干扰图纸。
- 核对阴影只用于需要的表现视图。
- 核对透明度不会冲淡剖切信息。
- 核对过滤器的目标类别正确。
- 核对过滤器条件没有空值漏项。
- 核对过滤器颜色有图例或文字说明。
- 核对未编号对象在 QA 视图清楚可见。
- 核对模板更新后没有破坏局部视图。
- 核对例外视图有明确命名或备注。
- 核对没有用元素级 Override 代替标准。
- 核对平面与剖面使用不同的表达规则。
- 核对立面没有显示无关内部对象。
- 核对三维表现视图不承担施工图信息。
- 核对图纸上的线宽以 PDF 为准。
- 核对文字在目标比例可读。
- 核对填充图案在 PDF 中不过密。
- 核对相同用途的视图视觉上可互相比较。
- 核对 Project Browser 可区分工作与发布视图。
- 核对复制视图后的模板未丢失。
- 核对出图前不再无记录地改模板。
- 核对模板修改后至少抽检平、立、剖三类。
- 核对最后 PDF 页没有隐藏/显示意外。
- 核对模板仍服务图纸信息而非单纯特效。
- 核对所有例外在提交前是有意为之。

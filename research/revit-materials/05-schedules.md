# Schedule：面积、门窗表、图例与数据驱动标注

## 适用场景

- 适用于房间面积表、门窗表、家具/洁具表、材料表、图例与课程项目的交付核查。
- 明细表应是模型数据的读视图，不是最后一天复制粘贴的文字表。
- 先用表找模型错误，再将表作为图纸上的正式信息。

## 核心原则

1. 先确认对象类别与参数，才开始建表。
2. 一张表只回答一个问题：数量、面积、编号、规格或 QA。
3. 门窗表依赖正确 Door/Window 类别与实例；不能由普通模型替代。[S1]
4. 表中的计算结果必须回到模型抽查，不把显示结果当成事实。
5. 当多个视图和图纸共享表时，保持字段和格式简单稳定。

## 房间面积表

- 房间面积表的前提是房间边界闭合、标高正确、Room 已放置。
- 墙、楼板开口、分隔线与 Room Bounding 设置会影响面积；先解决边界再修表。
- 字段至少包括 Number、Name、Level、Area；按课程要求加入部门、用途或备注。
- 用 Sorting/Grouping 按楼层或功能分组；合计只在需要汇总时显示。
- 面积单位、舍入和显示格式应在表内或项目单位中明确，避免不同图纸不一致。
- 若房间未放置或未封闭，应单独建 QA 表或在平面用颜色 Filter 标出。

## 门窗表

- Door Schedule 常用字段：Mark、Type Mark、Family and Type、Width、Height、Level、From Room、To Room、Comments。
- Window Schedule 常用字段：Mark、Type Mark、Family and Type、Width、Height、Sill Height、Level、Comments。
- 用实例 Mark 作为每樘编号，用 Type Mark/Family and Type 表示型号；不要把二者混为一谈。
- 窗宽高是类型还是实例取决于族设计；表格字段应反映真实参数归属。[S2]
- 同一门型多樘时，按需要选择逐实例列出或按类型汇总；不要为了好看牺牲编号可追踪性。
- 在门窗表前先建立门窗 Tag；Tag 与表读取同一套数据，能相互校验。

## 计算字段和条件格式

- Calculated Value 适合从已有可靠字段得到面积、合计长度或显示字符串。
- 计算前确认单位和空值行为；字符串拼接不能代替可计算的原始数值字段。
- Conditional Formatting 适合标红超限面积、空编号、异常门宽等 QA 状态。
- 条件格式应服务于审核，而非做彩色装饰；高对比色用完后要能解释含义。
- 课程交付可保留一张 QA 表，不必上图纸；正式表保持简洁。

## 明细表驱动标注

- 正确路径是：族/项目参数 → 标签 Label → 明细表字段 → 图纸核对。
- 门窗标签读取共享参数或类别可用参数时，表和图可同步更新。[S2]
- 不要在标签里手打规格；那会在改族或改编号时与表脱节。
- 图例可放置代表类型，配合类型名称、尺寸或说明；它不是实时数量统计表。
- 某类对象若需要独立计数，必须以正确类别、共享设置和实例放置方式建模。[S3]

## 方法步骤

1. 先在模型选中典型对象，核对类别、类型/实例参数和宿主。
2. 新建最小字段表，只显示身份和尺寸。
3. 将表按楼层、房间或类型排序，观察是否有异常空值、重复编号或漏项。
4. 修模型/参数，而不是用表格文字掩盖问题。
5. 增加需要的计算、筛选、分组和格式。
6. 建立对应 Tag，检查图面编号与表格一致。
7. 在图纸上放置正式表，预览 PDF 检查列宽、换行和分页。

## 优点

- 表能反向暴露对象类别错误、未编号实例和房间边界问题。
- 正确参数化后，改模型会同步更新数量、尺寸和标签。
- 一张清晰门窗表常比复杂三维表现更能证明 BIM 模型的完整性。

## 风险与坑

- 已加载但未放置的族不一定出现在常规明细表；明细通常统计项目中的实例。[S4]
- 族内 Array 的视觉数量可能不能直接作为内部子件数量出表，须实测共享/类别行为。[S3]
- 同一字段在类型和实例上各有一个时，容易出现看似相同但不一致的数据。
- 用普通文字替换 Tag、用 Generic Model 替换门窗，都会切断数据链。
- 合并单元格、过多隐藏字段和手工改表格式会降低后续维护性。

## 不适用情况

- 仅表现概念且无编号/数量要求的单张图，不必先投入完整表格体系。
- 无法保证模型边界和类别正确时，面积表和工程量表不应被用作正式依据。

## 课程作业建议

- 至少交付：房间面积表、门表、窗表；它们也是模型 QA 清单。
- 从第一天起给门窗编号，避免最后一天面对几十个空 Mark。
- 抽查表中三项数据，回到平面/立面确认实体、标高和标签都一致。
- 将未编号、未命名、零面积房间做成 QA 筛选或 Filter，交付前清零。
- 最终 PDF 中检查长表没有被裁掉，标题和单位可读。

## 明细表检查清单

- 确认表的类别与目标对象类别一致。
- 确认字段只保留读者需要的信息。
- 确认字段名称是清楚的人类语言。
- 确认 Door Mark 是实例级编号。
- 确认 Type Mark 的规则一致。
- 确认类型尺寸来自正确参数。
- 确认房间名称没有空值。
- 确认房间编号没有重复。
- 确认房间面积单位写清楚。
- 确认面积舍入符合任务书。
- 确认房间按楼层或功能正确排序。
- 确认合计只在需汇总处显示。
- 确认门表没有遗漏主要入口。
- 确认窗表没有漏掉幕墙门窗边界。
- 确认每条 Mark 能在图中找到。
- 确认图中 Tag 能在表中找到。
- 确认表中空值都已经解释或修复。
- 确认筛选条件没有排除关键对象。
- 确认过滤条件不会误伤相似类型。
- 确认计算字段采用数值而非手写文字。
- 确认计算字段的单位正确。
- 确认条件格式说明异常而非装饰。
- 确认 QA 表和正式表分开。
- 确认正式表不包含调试字段。
- 确认列宽在 Sheet 上可读。
- 确认文字不会被换行截断。
- 确认长表的分页或续表策略。
- 确认表标题含有明确对象范围。
- 确认不同表的同名字段语义一致。
- 确认共享参数没有被同名族参数冒充。
- 确认嵌套/阵列对象的计数经过实测。
- 确认未放置族没有被误当成数量。
- 确认样本对象已回到模型核查。
- 确认总数与视觉/计划数量相符。
- 确认导出 PDF 后表格没有裁切。
- 确认最终表由模型更新而非手改。
- 确认交付前重新刷新所有正式表。
- 确认表中没有遗留测试对象。
- 确认门窗高度与立面抽查相符。
- 确认房间面积与平面边界抽查相符。
- 确认表的排序能支持评阅顺序。
- 确认关键说明不靠颜色单独表达。
- 确认图例不被误用为数量表。
- 确认表格驱动的标注同步更新。
- 确认最终 Sheet 上表的字体可读。
- 确认数量异常先修模型再修表。
- 确认每张表都能回答一个明确问题。
- 确认表格是 BIM 数据链的一部分。
- 确认表格更新前项目已经保存。
- 确认排序规则便于按图纸检索。
- 确认异常值有明确处理责任。
- 确认提交版本不含临时测试字段。
- 确认最终数据能够从模型复现。

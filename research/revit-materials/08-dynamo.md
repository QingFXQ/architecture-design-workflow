# Dynamo：哪些重复劳动值得自动化，哪些不值得

## 适用场景

- 适用于课程项目中门窗编号、参数填写、批量视图/图纸管理、数据检查等重复任务。
- Dynamo 的价值在于重复、规则明确、可验证、可回滚的工作，而不是替代设计判断。
- Dynamo Player 可向非脚本用户暴露受控输入；Revit Pure 的公开说明展示了其让用户选择输入后运行脚本的用途。[S1][S2]

## 自动化决策四问

1. 该任务是否至少重复 20 次，或每次都要跨多个元素？
2. 输入规则是否能用参数、选择集、标高、房间或名称明确表达？
3. 输出是否能由明细表/Filter/抽样快速验证？
4. 出错后是否能撤销、在副本运行或以小样本重跑？
- 四项有一项回答“否”，优先手动或半自动。

## 值得自动化的任务

- 基于房间或楼层的门编号、家具编号、视图命名。
- 批量写入明确规则的参数，如前缀、备注、楼层代码。
- 创建规则标高、网格、视图或重复 Sheet 的初始结构。
- 从对象参数生成 QA 清单，例如缺 Mark、缺材质、错误高度。
- 批量选择/过滤相同类别后执行可预测修改。
- 批量统计开口面积、立面比例等已定义计算；Revit Pure 公开案例提到门编号、开口计算等脚本方向。[S2][S3]

## 不值得自动化的任务

- 方案空间布局、材料审美、剖面叙事和视图构图。
- 一次性只改 3—5 个对象的工作。
- 参数语义尚未确定、类别尚未清理的模型。
- 不能在输出后快速检查的几何重建或大规模删除。
- 截止日前首次使用的第三方 package 或网上下载的未知脚本。

## 安全方法步骤

1. 先在项目副本或小样本元素上运行。
2. 写出输入、规则、预期输出和不应改变的对象。
3. 在 Player 中给输入友好名称，只暴露必要输入。
4. 首次运行后立即用明细表、Filter 和随机抽查确认结果。
5. 保存运行前后版本；若规则改变，重新从小样本开始。
6. 脚本名称包含动作、范围和版本，例如 `DoorMark_ByRoom_v02`。

## Dynamo Player 的定位

- Player 适合把已验证脚本交给不进入 Dynamo 图形界面的使用者。[S1]
- 输入越少、语义越明确，越适合 Player。
- Player 不是免测试按钮；版本、项目参数和选择范围变化仍会改变结果。
- Revit Pure 指出早期 Player 的可用性/稳定性存在观察到的问题，因此脚本执行前后仍须校验。[S1]

## 课程作业建议

- 首选一个低风险脚本：按房间为门编号或批量加注释。
- 不要为了“用了 Dynamo”而把核心建模交给脚本。
- 在最终版本冻结后停止大批量脚本；只允许 QA 查询或可回滚的小修。
- 将脚本、输入说明、运行日期放在交付文件夹，便于复现。

## 优点

- 将重复键盘操作转为明确规则，减少漏改和命名不一致。
- 通过 Player 降低稳定脚本的使用门槛。
- QA 脚本能让数据质量问题提前可见。

## 风险与坑

- 自动化会高速放大错误规则；“快”不等于“正确”。
- 脚本若依赖特定参数名、类别或 package，换模板/版本可能失效。
- 脚本输出看起来合理，不代表没有覆盖错误范围；必须抽样复核。
- 复杂生成几何可能比原生系统构件更难编辑、出表和出图。

## 不适用情况

- 没有明确可验证规则的创作性工作。
- 没有备份、没有时间测试的临期批处理。
- 只需完成一个小模型的短作业。

## 脚本运行检查

- 写清脚本目的。
- 写清 Revit 版本。
- 写清输入对象类别。
- 写清输入参数名称。
- 写清输出参数名称。
- 写清不应改动的对象。
- 保存运行前副本。
- 先选少量样本。
- 记录样本预期输出。
- 样本运行后查表。
- 样本运行后查平面。
- 样本运行后查三维。
- 检查其他楼层未误改。
- 检查其他类别未误改。
- 检查编号没有重复。
- 检查编号没有空值。
- 检查参数类型正确。
- 检查实例/类型归属正确。
- Player 输入名称可理解。
- Player 不暴露危险选项。
- 脚本名含动作和版本。
- 记录输出计数。
- 运行后检查 warnings。
- 失败时可撤销。
- 大批量前有备份。
- 大批量后有抽样。
- 不依赖临时视图。
- 不依赖隐式选择集。
- package 版本已记录。
- 来源可信且可说明。
- 输入规则可用人话说明。
- 输出规则可用人话说明。
- 空值规则明确。
- 异常值规则明确。
- 重复运行是否安全已判断。
- 删除动作先停止复核。
- 重建几何先停止复核。
- 宿主变化先停止复核。
- 临期不引入新 package。
- 脚本只解决重复劳动。
- 脚本不替代设计判断。
- 脚本不替代模型 QA。
- 运行后更新 PDF 样张。
- 团队理解运行范围。
- 运行时间符合时间盒。
- 失败版本可回退。
- 脚本与项目版本对应。
- 人工例外不会被覆盖。
- 输入范围被限制。
- 生成元素类别明确。
- 模型性能没有异常下降。
- 规则变化时回到样本。
- 每次升级有版本号。
- 输出能由表格证明。
- 提交前停止批量运行。
- 最终模型仍可手工维护。
- 自动化收益大于测试成本。
- 运行记录与交付一起保存。
- 所有结果仍能被人工解释。
- 自动化保持可验证可回滚。
- 只对确定规则执行。
- 每次操作有明确范围。
- 最终输出没有调试数据。
- 脚本失败不会阻断交付。
- 完成后清理测试元素。
- 优先低风险任务。
- 保留原始模型版本。
